The question: what makes concrete strong?

Concrete is cement, water, sand, gravel and a few extras such as blast furnace slag, fly ash (both left over from other industries) and a chemical “superplasticizer” that makes the mix flow. Engineers want to know how strong a mix will be before they pour it, because the strength is tested by crushing a sample, and by then the mix has already set for 28 days.

This page asks: how well can we predict the compressive strength of concrete (in megapascals, MPa) from what is in the mix and how old it is, and which ingredients matter most?

The relationship is not simple, for two reasons:

  • It is nonlinear. Concrete gains strength quickly in the first weeks, then more and more slowly. Doubling the age does not double the strength.
  • It has interactions. Slag, for example, adds almost nothing to young concrete, because it reacts slowly, and a lot to concrete that has had a month or more to set.

A straight-line regression (see the regression page) misses both. Gradient boosting finds them on its own. It builds a prediction from hundreds of small decision trees, one after another, each one correcting the mistakes of those before it. It is one of the most accurate methods for tables of numbers, and the one that wins many prediction contests.

Gradient boosting and a random forest both add up many trees, but in opposite ways:

Random forest Gradient boosting
Trees are grown independently, in parallel one after another
Each tree is deep, and fitted to the data small, and fitted to the mistakes so far
Trees are combined by averaging adding up, each scaled down
Main danger few: more trees never overfit too many trees overfit

3. The model step by step, with formulas

Step 1: start from a constant

The simplest possible prediction is the same number for every sample. For squared error it is the mean of the outcome:

\[F_0(x) = \bar{y}\]

Here \(F_0\) = 35.6 MPa for everyone.

Step 2: the mistakes of the current model

The model is not good, so it makes mistakes. Boosting measures them with a loss function, a number that is large when the predictions are bad. For a continuous outcome the usual loss is half the squared error:

\[L(y, F) = \tfrac{1}{2}\,(y - F(x))^2\]

To make the model better, we need to know in which direction to change each prediction. That direction is the negative gradient of the loss with respect to the prediction. For squared error it is simply:

\[-\frac{\partial L}{\partial F(x_i)} = y_i - F(x_i) = r_i\]

The negative gradient is the residual: the actual strength minus the predicted strength. A positive residual says “predict higher for this sample”, a negative one “predict lower”. This is why the method is called gradient boosting: with another loss (absolute error, Poisson deviance…) the same recipe works, and only the “residual” changes.

Step 3: fit a small tree to the mistakes

A small regression tree \(h_1\) is fitted with the residuals as its outcome. It finds groups of samples that the current model gets wrong in the same direction (for instance young, low-cement concrete, which \(F_0\) overestimates), and predicts the average residual of each group. How a single tree finds its groups is explained on the decision tree page.

Step 4: add the tree, scaled down

The new tree is added to the model, but only a fraction of it, the learning rate \(\nu\) (also called shrinkage or eta, typically 0.01 to 0.3):

\[F_1(x) = F_0(x) + \nu \, h_1(x)\]

Why not add all of it, with \(\nu = 1\)? Because each tree is fitted to the noise as well as the signal. Taking only a small step each time makes the model learn the pattern that many trees agree on, and not the accident of one.

Step 5: repeat

Compute the new residuals \(y - F_1(x)\), fit a tree \(h_2\) to them, and add it. After \(M\) rounds:

\[F_m(x) = F_{m-1}(x) + \nu \, h_m(x) \qquad\Longrightarrow\qquad F_M(x) = \bar{y} + \nu \sum_{m=1}^{M} h_m(x)\]

The final prediction is the constant plus the sum of all the scaled trees. Every tree is small, but together they can draw a very flexible curve.

Step 6: what xgboost adds

xgboost (“extreme gradient boosting”) follows the same recipe with two refinements. It uses the second derivative of the loss as well (a better step than the gradient alone), and it penalises complex trees. Each tree is chosen to minimise

\[\sum_i \left[ g_i f(x_i) + \tfrac{1}{2} h_i f(x_i)^2 \right] + \gamma T + \tfrac{1}{2}\lambda \sum_j w_j^2\]

where \(g_i\) and \(h_i\) are the first and second derivatives of the loss for sample \(i\), \(T\) is the number of leaves, \(w_j\) the value in leaf \(j\), and \(\gamma\) and \(\lambda\) are penalties. For squared error \(g_i = F(x_i) - y_i\) (minus the residual) and \(h_i = 1\), so the best value in a leaf is

\[w_j = \frac{\sum_{i \in \text{leaf } j} r_i}{n_j + \lambda}\]

the average residual in the leaf, pulled towards zero by \(\lambda\) (the lambda setting). The sum of \(h_i\) in a leaf, here just the number of samples \(n_j\), is what the setting min_child_weight limits: leaves resting on very few samples are not allowed.

Step 7: boosting by hand

We can do all this with rpart, in a few lines. Each tree is small (two levels, so at most four leaves), and the learning rate is \(\nu = 0.3\):

Code 
boost_by_hand <- function(train, test, nu, M, depth = 2) {
  f_train <- rep(mean(train$strength), nrow(train))            # step 1: the constant
  f_test  <- rep(mean(train$strength), nrow(test))
  residuals <- matrix(NA, nrow(train), M + 1)                  # the residuals after every step
  residuals[, 1] <- train$strength - f_train
  rmse <- data.frame(trees = 0:M, train = NA, test = NA)
  rmse[1, 2:3] <- c(sd(train$strength) * sqrt((nrow(train) - 1) / nrow(train)),
                    sqrt(mean((test$strength - f_test)^2)))
  trees <- list()
  for (m in 1:M) {
    d <- train[predictors]
    d$r <- train$strength - f_train                            # step 2: the residuals
    trees[[m]] <- rpart(r ~ ., d, control = rpart.control(maxdepth = depth, cp = 0, xval = 0))  # step 3
    f_train <- f_train + nu * predict(trees[[m]], train)       # step 4: add, scaled down
    f_test  <- f_test  + nu * predict(trees[[m]], test)
    residuals[, m + 1] <- train$strength - f_train
    rmse[m + 1, 2:3] <- c(sqrt(mean(residuals[, m + 1]^2)), sqrt(mean((test$strength - f_test)^2)))
  }
  list(rmse = rmse, residuals = residuals, trees = trees)
}
hand <- boost_by_hand(train, test, nu = 0.3, M = 100)

4. The settings

A boosted model has a few settings (hyperparameters) that the data cannot tell us. Each one controls how fast the model learns and how complex it can become:

Setting (xgboost name) What it does Typical values Too low Too high
Number of trees (nrounds) How many correction rounds 100 to several thousand Underfits Overfits
Learning rate (eta) How much of each tree is added 0.01 to 0.3 Needs very many trees Jumpy; overfits sooner
Tree depth (max_depth) Levels per tree. Depth 1 is a stump (no interactions), depth 2 allows two-way interactions, and so on 2 to 8 Misses interactions Overfits; slow
Row sampling (subsample) Share of the samples used for each tree 0.5 to 1 More noise No randomness against overfitting
Column sampling (colsample_bytree) Share of the predictors used for each tree 0.5 to 1 Trees too weak Trees too alike
Minimum child weight (min_child_weight) Fewest samples a leaf may rest on (for squared error) 1 to 10 Leaves fitted to noise Underfits
Penalties (lambda, gamma) Shrink leaf values (lambda) and ask a split to pay for itself (gamma) 0 to 10 Underfits

The settings work together. A smaller learning rate needs more trees; deeper trees need fewer. A good rule: set the learning rate low enough to be smooth (0.05 to 0.1), and let cross-validation choose the number of trees.

Learning rate and number of trees

To compare settings without touching the test set, we use 5-fold cross-validation on the training data: the training samples are split into five parts; the model is fitted five times, each time to four parts, and the error is measured on the fifth. xgb.cv() does it, and gives the error after every tree. We give it the same folds each time, so that the settings are compared on the same data.

Code 
set.seed(1)
folds <- split(sample(nrow(train)), rep(1:5, length.out = nrow(train)))

# cross-validation for a set of settings: returns the error after every tree
cv_run <- function(nrounds, early = NULL, ...) {
  params <- list(objective = "reg:squarederror", nthread = 1, ...)
  xgb.cv(params = params, data = d_train, nrounds = nrounds, folds = folds,
         early_stopping_rounds = early, verbose = 0)
}

Overfitting: training error against validation error

A model with enough trees can learn the training data by heart, noise included. The training error then keeps falling, while the error on new data stops improving, and may turn up. To see it, we use larger trees (depth 6), where it happens sooner, and watch both errors tree by tree. The cross-validation error is the error on the part left out, the validation error.

Early stopping uses this: stop adding trees when the validation error has not improved for a number of rounds (here 30), and keep the number of trees that was best. The number of trees is therefore not set by hand but found by cross-validation. This is the usual way to choose it.

Trying every combination is costly, so we use a small grid: three learning rates, three depths, two minimum child weights and two row sampling rates, 36 combinations. 7. Interpreting the model

A boosted model is a black box in the sense that no single number says what a variable does. Three tools open it, from the whole model down to one sample.

Which predictors matter? Gain against permutation

There are two common ways to rank the predictors.

  • Gain is built into xgboost: the total improvement in the loss from all the splits on a predictor, as a share of the total. It is computed on the training data and says what the model used.
  • Permutation importance shuffles one predictor in the test set, so that it carries no information, and measures how much the error increases. It says what the model needs on new data. We write it by hand; it is only a loop.
Code 
gain <- as.data.frame(xgb.importance(model = fit))
gain <- setNames(gain$Gain, gain$Feature)[predictors]

set.seed(6)
baseline <- sqrt(mean((test$strength - predict(fit, x_test))^2))
permutation <- sapply(predictors, function(v) mean(replicate(20, {
  shuffled <- x_test
  shuffled[, v] <- sample(shuffled[, v])
  sqrt(mean((test$strength - predict(fit, shuffled))^2)) - baseline
})))

importance <- rbind(data.frame(predictor = predictors, share = gain / sum(gain), method = "Gain"),
                    data.frame(predictor = predictors, share = permutation / sum(permutation), method = "Permutation"))
importance$predictor <- factor(nice[importance$predictor], levels = nice[names(sort(permutation))])
ggplot(importance, aes(share, predictor, fill = method)) +
  geom_col(position = position_dodge(width = 0.8), width = 0.7) +
  scale_fill_manual(values = colours[1:2], guide = guide_legend(reverse = TRUE)) +
  scale_x_continuous(labels = scales::percent, expand = expansion(mult = c(0, 0.05))) +
  labs(x = "Share of the total importance", y = NULL, fill = NULL) +
  theme_bw() + theme(legend.position = "bottom")
Code 
rank_gain <- names(sort(gain, decreasing = TRUE)); rank_perm <- names(sort(permutation, decreasing = TRUE))

By gain the order is Age (days), Cement, Water; by permutation it is Age (days), Cement, Water. The top predictor, age (days), accounts for 37% of the permutation importance: shuffling it raises the test RMSE by 12.1 MPa. The two measures give the same order here, but they need not. Gain tends to favour predictors with many possible split points, and both measures share the credit unfairly between predictors that are correlated (here water and superplasticizer, for example). Importance says how much the model uses a predictor, not in which direction, and not whether changing it would change the strength.

Which way? Partial dependence

A partial dependence plot shows the average prediction as one predictor moves across its range. For each value \(v\), we set the predictor to \(v\) in every training sample, predict, and average:

\[\text{PD}(v) = \frac{1}{n} \sum_{i=1}^{n} \hat{F}\left(v,\; x_{i,\text{other}}\right)\]

Code 
partial_dependence <- function(fit, x, feature, grid) {
  data.frame(value = grid,
             prediction = sapply(grid, function(v) { x[, feature] <- v; mean(predict(fit, x)) }))
}
top4 <- rank_perm[1:4]

}))

One sample at a time: SHAP values

SHAP values (SHapley Additive exPlanations; Lundberg & Lee, 2017) split the prediction for one sample among the predictors, so that

\[\hat{F}(x) = \underbrace{\phi_0}_{\text{average prediction}} + \phi_{\text{cement}} + \phi_{\text{water}} + \dots + \phi_{\text{age}}\]

Each \(\phi_j\) is the contribution of predictor \(j\) for this sample: how many MPa it moves the prediction up or down from the average. For tree models they can be computed exactly and quickly, and xgboost does it with predict(..., predcontrib = TRUE):

8. Caveats

Tuning sensitivity. Boosting is more sensitive to its settings than a random forest. A learning rate that is too high, or too many deep trees, can overfit badly, as the charts above show. Always choose the number of trees by cross-validation or a validation set, never by what looks good on the training data, and never on the test set. The tuning grid here is small; with more computing time one would search more finely (random search, or Bayesian optimisation).

Extrapolation. A tree predicts an average of samples it has seen, so the prediction stays flat outside the range of the data. A boosted model cannot predict that concrete with more cement than any in the data will be even stronger; and the model knows nothing about concrete older than a year. A linear model would extrapolate (not necessarily well). Be careful with mixes unlike the training data.

Code

  annotate("text", x = max(train$cement), y = min(ext$prediction), label = "most cement in the data",

Beyond the dashed line the prediction is a flat line: it is not a forecast, it is only what the model does at the edge of what it knows.

Importance is not causation. The predictors in these data are related to each other: engineers add superplasticizer in order to use less water, and mixes with slag are designed differently from those without. So a large importance or a steep partial dependence for water does not mean that adding water to a given concrete will lower its strength by that amount. The model shows what goes with strength in these data, which is what prediction needs. Causal questions need an experiment or a causal design.

Other things to keep in mind.

  • The data are one study, from one laboratory: the model describes these mixes and materials. Cement from other suppliers may behave differently.
  • The 25 duplicated rows may sit in both the training and the validation parts of a cross-validation fold, which makes the validation error a little too optimistic. The test set may share a few of them too.
  • The test result rests on 206 samples and one random split. Repeating the split, or using nested cross-validation, would give a more stable estimate.
  • Boosting predicts the average strength for a mix. It does not by itself give a prediction interval; for safety decisions you need one (for example from quantile loss, or conformal prediction).

9. Reporting the results in APA style

Report a predictive model as you would any other: what was predicted and from what, how the data were split, how the settings were chosen, and how well the model did on data it had not seen.

Method:

We predicted the compressive strength of concrete (MPa) from seven mix ingredients and age, using gradient boosting with squared-error loss (xgboost, version 3.2.1.1; Chen & Guestrin, 2016). The 1,030 samples (Yeh, 1998) were split at random into a training set (n = 824) and a test set (n = 206). The settings were chosen on the training set by five-fold cross-validation over a grid of 36 combinations of learning rate, tree depth, minimum child weight and row sampling; the number of trees was chosen by early stopping. The selected model had a learning rate of 0.1, a maximum depth of 4, a minimum child weight of 1, row sampling of 1, column sampling of 0.8 and 888 trees. We compared it on the test set with linear regression, a pruned regression tree and a random forest with default settings (ranger; Wright & Ziegler, 2017). Predictors were explained with gain, permutation importance, partial dependence and SHAP values (Lundberg & Lee, 2017).

Results:

On the test set, gradient boosting predicted concrete strength with an RMSE of 3.93 MPa, an MAE of 2.78 MPa and R² = .95. This was better than linear regression (RMSE = 10.43, R² = .61) and a single regression tree (RMSE = 9.60, R² = .67), and better than an untuned random forest (RMSE = 5.66, R² = .89). The most important predictors were age (days), cement, water (permutation importance), and the partial dependence plots showed that strength rose steeply with age at first and then levelled off.

## The question: what makes concrete strong?

Concrete is cement, water, sand, gravel and a few extras such as blast furnace slag, fly ash (both left over from other industries) and a chemical "superplasticizer" that makes the mix flow. Engineers want to know how strong a mix will be **before** they pour it, because the strength is tested by crushing a sample, and by then the mix has already set for 28 days.

This page asks: **how well can we predict the compressive strength of concrete (in megapascals, MPa) from what is in the mix and how old it is, and which ingredients matter most?**

The relationship is not simple, for two reasons:

- **It is nonlinear.** Concrete gains strength quickly in the first weeks, then more and more slowly. Doubling the age does not double the strength.
- **It has interactions.** Slag, for example, adds almost nothing to young concrete, because it reacts slowly, and a lot to concrete that has had a month or more to set.

A straight-line regression ([see the regression page](EXAMPLE_REGULARIZED_REGRESSION.Rmd)) misses both. **Gradient boosting** finds them on its own. It builds a prediction from hundreds of small decision trees, **one after another**, each one correcting the mistakes of those before it. It is one of the most accurate methods for tables of numbers, and the one that wins many prediction contests.

Gradient boosting and a [random forest](EXAMPLE_RANDOM_FOREST.Rmd) both add up many trees, but in opposite ways:

| | Random forest | Gradient boosting |
|---|---|---|
| Trees are grown | independently, in parallel | one after another |
| Each tree is | deep, and fitted to the data | small, and fitted to the mistakes so far |
| Trees are combined by | averaging | adding up, each scaled down |
| Main danger | few: more trees never overfit | too many trees overfit |

## 3. The model step by step, with formulas

### Step 1: start from a constant

The simplest possible prediction is the same number for every sample. For squared error it is the **mean** of the outcome:

$$F_0(x) = \bar{y}$$

Here $F_0$ = `r f1(mean(train$strength))` MPa for everyone.

### Step 2: the mistakes of the current model

The model is not good, so it makes mistakes. Boosting measures them with a **loss function**, a number that is large when the predictions are bad. For a continuous outcome the usual loss is half the squared error:

$$L(y, F) = \tfrac{1}{2}\,(y - F(x))^2$$

To make the model better, we need to know in which direction to change each prediction. That direction is the **negative gradient** of the loss with respect to the prediction. For squared error it is simply:

$$-\frac{\partial L}{\partial F(x_i)} = y_i - F(x_i) = r_i$$

**The negative gradient is the residual**: the actual strength minus the predicted strength. A positive residual says "predict higher for this sample", a negative one "predict lower". This is why the method is called *gradient* boosting: with another loss (absolute error, Poisson deviance...) the same recipe works, and only the "residual" changes.

### Step 3: fit a small tree to the mistakes

A small regression tree $h_1$ is fitted with the **residuals as its outcome**. It finds groups of samples that the current model gets wrong in the same direction (for instance young, low-cement concrete, which $F_0$ overestimates), and predicts the average residual of each group. [How a single tree finds its groups is explained on the decision tree page](EXAMPLE_DECISION_TREE.rmd).

### Step 4: add the tree, scaled down

The new tree is **added to the model**, but only a fraction of it, the **learning rate** $\nu$ (also called shrinkage or `eta`, typically 0.01 to 0.3):

$$F_1(x) = F_0(x) + \nu \, h_1(x)$$

Why not add all of it, with $\nu = 1$? Because each tree is fitted to the noise as well as the signal. Taking only a small step each time makes the model learn the pattern that many trees agree on, and not the accident of one.

### Step 5: repeat

Compute the new residuals $y - F_1(x)$, fit a tree $h_2$ to them, and add it. After $M$ rounds:

$$F_m(x) = F_{m-1}(x) + \nu \, h_m(x) \qquad\Longrightarrow\qquad F_M(x) = \bar{y} + \nu \sum_{m=1}^{M} h_m(x)$$

The final prediction is the constant plus the sum of all the scaled trees. Every tree is small, but together they can draw a very flexible curve.

### Step 6: what xgboost adds

`xgboost` ("extreme gradient boosting") follows the same recipe with two refinements. It uses the **second derivative** of the loss as well (a better step than the gradient alone), and it **penalises** complex trees. Each tree is chosen to minimise

$$\sum_i \left[ g_i f(x_i) + \tfrac{1}{2} h_i f(x_i)^2 \right] + \gamma T + \tfrac{1}{2}\lambda \sum_j w_j^2$$

where $g_i$ and $h_i$ are the first and second derivatives of the loss for sample $i$, $T$ is the number of leaves, $w_j$ the value in leaf $j$, and $\gamma$ and $\lambda$ are penalties. For squared error $g_i = F(x_i) - y_i$ (minus the residual) and $h_i = 1$, so the best value in a leaf is

$$w_j = \frac{\sum_{i \in \text{leaf } j} r_i}{n_j + \lambda}$$

the **average residual in the leaf**, pulled towards zero by $\lambda$ (the `lambda` setting). The sum of $h_i$ in a leaf, here just the number of samples $n_j$, is what the setting `min_child_weight` limits: leaves resting on very few samples are not allowed.

### Step 7: boosting by hand

We can do all this with `rpart`, in a few lines. Each tree is **small** (two levels, so at most four leaves), and the learning rate is $\nu = 0.3$:

```{r by_hand_fun}
boost_by_hand <- function(train, test, nu, M, depth = 2) {
  f_train <- rep(mean(train$strength), nrow(train))            # step 1: the constant
  f_test  <- rep(mean(train$strength), nrow(test))
  residuals <- matrix(NA, nrow(train), M + 1)                  # the residuals after every step
  residuals[, 1] <- train$strength - f_train
  rmse <- data.frame(trees = 0:M, train = NA, test = NA)
  rmse[1, 2:3] <- c(sd(train$strength) * sqrt((nrow(train) - 1) / nrow(train)),
                    sqrt(mean((test$strength - f_test)^2)))
  trees <- list()
  for (m in 1:M) {
    d <- train[predictors]
    d$r <- train$strength - f_train                            # step 2: the residuals
    trees[[m]] <- rpart(r ~ ., d, control = rpart.control(maxdepth = depth, cp = 0, xval = 0))  # step 3
    f_train <- f_train + nu * predict(trees[[m]], train)       # step 4: add, scaled down
    f_test  <- f_test  + nu * predict(trees[[m]], test)
    residuals[, m + 1] <- train$strength - f_train
    rmse[m + 1, 2:3] <- c(sqrt(mean(residuals[, m + 1]^2)), sqrt(mean((test$strength - f_test)^2)))
  }
  list(rmse = rmse, residuals = residuals, trees = trees)
}
hand <- boost_by_hand(train, test, nu = 0.3, M = 100)
```

## 4. The settings

A boosted model has a few settings (**hyperparameters**) that the data cannot tell us. Each one controls how fast the model learns and how complex it can become:

| Setting (`xgboost` name) | What it does | Typical values | Too low | Too high |
|---|---|---|---|---|
| Number of trees (`nrounds`) | How many correction rounds | 100 to several thousand | Underfits | Overfits |
| Learning rate (`eta`) | How much of each tree is added | 0.01 to 0.3 | Needs very many trees | Jumpy; overfits sooner |
| Tree depth (`max_depth`) | Levels per tree. Depth 1 is a stump (no interactions), depth 2 allows two-way interactions, and so on | 2 to 8 | Misses interactions | Overfits; slow |
| Row sampling (`subsample`) | Share of the samples used for each tree | 0.5 to 1 | More noise | No randomness against overfitting |
| Column sampling (`colsample_bytree`) | Share of the predictors used for each tree | 0.5 to 1 | Trees too weak | Trees too alike |
| Minimum child weight (`min_child_weight`) | Fewest samples a leaf may rest on (for squared error) | 1 to 10 | Leaves fitted to noise | Underfits |
| Penalties (`lambda`, `gamma`) | Shrink leaf values (`lambda`) and ask a split to pay for itself (`gamma`) | 0 to 10 | | Underfits |

The settings **work together**. A smaller learning rate needs more trees; deeper trees need fewer. A good rule: set the learning rate low enough to be smooth (0.05 to 0.1), and let cross-validation choose the number of trees.

### Learning rate and number of trees

To compare settings without touching the test set, we use **5-fold cross-validation** on the training data: the training samples are split into five parts; the model is fitted five times, each time to four parts, and the error is measured on the fifth. `xgb.cv()` does it, and gives the error after every tree. We give it the same folds each time, so that the settings are compared on the same data.

```{r folds}
set.seed(1)
folds <- split(sample(nrow(train)), rep(1:5, length.out = nrow(train)))

# cross-validation for a set of settings: returns the error after every tree
cv_run <- function(nrounds, early = NULL, ...) {
  params <- list(objective = "reg:squarederror", nthread = 1, ...)
  xgb.cv(params = params, data = d_train, nrounds = nrounds, folds = folds,
         early_stopping_rounds = early, verbose = 0)
}
```

A model with enough trees can learn the training data by heart, noise included. The training error then keeps falling, while the error on new data stops improving, and may turn up. ## 7. Interpreting the model

A boosted model is a black box in the sense that no single number says what a variable does. Three tools open it, from the whole model down to one sample.

### Which predictors matter? Gain against permutation

There are two common ways to rank the predictors.

- **Gain** is built into xgboost: the total improvement in the loss from all the splits on a predictor, as a share of the total. It is computed on the training data and says what the model **used**.
- **Permutation importance** shuffles one predictor in the test set, so that it carries no information, and measures how much the error **increases**. It says what the model **needs** on new data. We write it by hand; it is only a loop.

```{r importance}
gain <- as.data.frame(xgb.importance(model = fit))
gain <- setNames(gain$Gain, gain$Feature)[predictors]

set.seed(6)
baseline <- sqrt(mean((test$strength - predict(fit, x_test))^2))
permutation <- sapply(predictors, function(v) mean(replicate(20, {
  shuffled <- x_test
  shuffled[, v] <- sample(shuffled[, v])
  sqrt(mean((test$strength - predict(fit, shuffled))^2)) - baseline
})))

importance <- rbind(data.frame(predictor = predictors, share = gain / sum(gain), method = "Gain"),
                    data.frame(predictor = predictors, share = permutation / sum(permutation), method = "Permutation"))
importance$predictor <- factor(nice[importance$predictor], levels = nice[names(sort(permutation))])
ggplot(importance, aes(share, predictor, fill = method)) +
  geom_col(position = position_dodge(width = 0.8), width = 0.7) +
  scale_fill_manual(values = colours[1:2], guide = guide_legend(reverse = TRUE)) +
  scale_x_continuous(labels = scales::percent, expand = expansion(mult = c(0, 0.05))) +
  labs(x = "Share of the total importance", y = NULL, fill = NULL) +
  theme_bw() + theme(legend.position = "bottom")
rank_gain <- names(sort(gain, decreasing = TRUE)); rank_perm <- names(sort(permutation, decreasing = TRUE))
```

By gain the order is `r paste(nice[rank_gain][1:3], collapse = ", ")`; by permutation it is `r paste(nice[rank_perm][1:3], collapse = ", ")`. The top predictor, `r tolower(nice[rank_perm[1]])`, accounts for `r pct(permutation[[rank_perm[1]]] / sum(permutation))` of the permutation importance: shuffling it raises the test RMSE by `r f1(permutation[[rank_perm[1]]])` MPa. The two measures `r if (identical(rank_gain, rank_perm)) "give the same order here" else "agree on the main players and differ on the smaller ones"`, but they need not. Gain tends to favour predictors with many possible split points, and both measures share the credit unfairly between predictors that are correlated (here water and superplasticizer, for example). **Importance says how much the model uses a predictor, not in which direction, and not whether changing it would change the strength.**

### Which way? Partial dependence

A **partial dependence** plot shows the average prediction as one predictor moves across its range. For each value $v$, we set the predictor to $v$ in **every** training sample, predict, and average:

$$\text{PD}(v) = \frac{1}{n} \sum_{i=1}^{n} \hat{F}\left(v,\; x_{i,\text{other}}\right)$$

```{r pdp_fun}
partial_dependence <- function(fit, x, feature, grid) {
  data.frame(value = grid,
             prediction = sapply(grid, function(v) { x[, feature] <- v; mean(predict(fit, x)) }))
}
top4 <- rank_perm[1:4]
pd <- do.call(rbind, lapply(top4, function(v) {
  grid <- seq(quantile(train[[v]], 0.01), quantile(train[[v]], 0.99), length.out = 40)
  cbind(feature = nice[[v]], partial_dependence(fit, x_train, v, grid))
}))
pd$feature <- factor(pd$feature, levels = nice[top4])
```

```{r pdp, fig.height = 5.5}
ggplot(pd, aes(value, prediction)) +
  geom_line(colour = colours[1], linewidth = 0.9) +
  facet_wrap(~ feature, scales = "free_x") +
  labs(x = "Value of the predictor", y = "Average predicted strength (MPa)") +
  theme_bw()
```

These are the shapes the straight line could not draw. Strength rises quickly with age and then flattens; it rises with cement; it falls with water. Where a curve is flat, the model sees no further change. The curve is only a summary of the average: if the effect of a predictor depends on another (an interaction), the average hides it. A partial dependence for **two** predictors at once shows it. Here is the effect of slag, with the age set to 3 days, 28 days and one year for every sample:

```{r pdp_interaction, fig.height = 4}
slag_grid <- seq(0, quantile(train$slag, 0.99), length.out = 40)
pd_int <- do.call(rbind, lapply(c(3, 28, 365), function(a) {
  x_age <- x_train; x_age[, "age"] <- a                 # every sample gets this age
  cbind(age = paste(a, "days"), partial_dependence(fit, x_age, "slag", slag_grid))
}))
pd_int$age <- factor(pd_int$age, levels = c("3 days", "28 days", "365 days"))
ggplot(pd_int, aes(value, prediction, colour = age)) +
  geom_line(linewidth = 0.9) +
  scale_colour_manual(values = colours[1:3]) +
  labs(x = "Blast furnace slag (kg per m³)", y = "Average predicted strength (MPa)", colour = "Age") +
  theme_bw() + theme(legend.position = "bottom")

```

The lines are far from parallel: going from no slag to `r num(round(max(slag_grid)))` kg changes the predicted strength by `r f1(rise[["3 days"]])` MPa at 3 days, `r f1(rise[["28 days"]])` MPa at 28 days and `r f1(rise[["365 days"]])` MPa at one year. The model has found the interaction of section 2 without being told.

### One sample at a time: SHAP values

**SHAP values** (SHapley Additive exPlanations; Lundberg & Lee, 2017) split the prediction for one sample among the predictors, so that

$$\hat{F}(x) = \underbrace{\phi_0}_{\text{average prediction}} + \phi_{\text{cement}} + \phi_{\text{water}} + \dots + \phi_{\text{age}}$$

Each $\phi_j$ is the contribution of predictor $j$ for this sample: how many MPa it moves the prediction up or down from the average. For tree models they can be computed exactly and quickly, and `xgboost` does it with `predict(..., predcontrib = TRUE)`:

```{r shap}
shap <- predict(fit, x_test, predcontrib = TRUE)
colnames(shap)
# the contributions and the (Intercept) column (the average prediction) add up to the prediction
all.equal(unname(rowSums(shap)), unname(predict(fit, x_test)), tolerance = 1e-4)
```

The last column, `(Intercept)`, is $\phi_0$. The check shows that for every test sample, the contributions add up to the prediction. Here are two samples: the one the model predicts to be strongest, and the one it predicts to be weakest:

```{r shap_two, fig.height = 5}
pred_test <- unname(predict(fit, x_test))
two <- c(strong = which.max(pred_test), weak = which.min(pred_test))
shap_two <- do.call(rbind, lapply(names(two), function(k) {

                             labels = c(paste0("Strongest predicted: ", f1(pred_test[i]), " MPa"),

             label = paste0(nice[predictors], " = ", sapply(x_test[i, predictors], function(v) format(v, digits = 3))),
             shap = shap[i, predictors])

  geom_col() +

  facet_wrap(~ sample, scales = "free_y", ncol = 1) +
  scale_fill_manual(values = colours[1:2]) +
  labs(x = "Contribution to the prediction (MPa)", y = NULL, fill = "Prediction") +
```

Start from the average prediction, `r f1(base)` MPa. For the strongest sample, the bars to the right push the prediction up, to `r f1(pred_test[two[["strong"]]])` MPa, and for the weakest the bars to the left pull it down to `r f1(pred_test[two[["weak"]]])` MPa. The labels show the value of each predictor in that sample, so each bar can be read as a sentence ("with this much water, the prediction goes down by so many MPa").

Averaging the size of the SHAP values over all test samples gives a **global** importance that, unlike gain, is based on what the model does for each sample. Plotting all of them shows the **direction** too:

## 8. Caveats

**Tuning sensitivity.** Boosting is more sensitive to its settings than a random forest. A learning rate that is too high, or too many deep trees, can overfit badly, as the charts above show. Always choose the number of trees by cross-validation or a validation set, never by what looks good on the training data, and never on the test set. The tuning grid here is small; with more computing time one would search more finely (random search, or Bayesian optimisation).

**Extrapolation.** A tree predicts an average of samples it has seen, so the prediction **stays flat outside the range of the data**. A boosted model cannot predict that concrete with more cement than any in the data will be even stronger; and the model knows nothing about concrete older than a year. A linear model would extrapolate (not necessarily well). Be careful with mixes unlike the training data.

```{r extrapolation, fig.height = 3.5}
g <- seq(300, 700, length.out = 60)
ext <- partial_dependence(fit, x_train, "cement", g)
ggplot(ext, aes(value, prediction)) +
  geom_line(colour = colours[1], linewidth = 0.9) +
  geom_vline(xintercept = max(train$cement), linetype = "dashed", colour = "grey40") +
  annotate("text", x = max(train$cement), y = min(ext$prediction), label = "most cement in the data",
           hjust = 1.05, vjust = -0.5, colour = "grey20") +
  labs(x = "Cement (kg per m³)", y = "Average predicted strength (MPa)") +
  theme_bw()
```

Beyond the dashed line the prediction is a flat line: it is not a forecast, it is only what the model does at the edge of what it knows.

**Importance is not causation.** The predictors in these data are related to each other: engineers add superplasticizer **in order to** use less water, and mixes with slag are designed differently from those without. So a large importance or a steep partial dependence for water does not mean that adding water to a given concrete will lower its strength by that amount. The model shows what **goes with** strength in these data, which is what prediction needs. Causal questions need an experiment or a causal design.

**Other things to keep in mind.**

- The data are one study, from one laboratory: the model describes **these** mixes and materials. Cement from other suppliers may behave differently.
- The `r n_dup` duplicated rows may sit in both the training and the validation parts of a cross-validation fold, which makes the validation error a little too optimistic. The test set may share a few of them too.
- The test result rests on `r nrow(test)` samples and one random split. Repeating the split, or using nested cross-validation, would give a more stable estimate.
- Boosting predicts the **average** strength for a mix. It does not by itself give a prediction interval; for safety decisions you need one (for example from quantile loss, or conformal prediction).

## 10. Summary

| | |
|---|---|
| **When** | A continuous outcome, a table of numbers, curved effects and interactions you do not want to specify by hand |
| **Idea** | Start from the mean; fit a small tree to the residuals; add it, scaled by a learning rate; repeat |
| **Loss and gradient** | Squared error: the negative gradient is the residual. Other losses give other "residuals" |
| **How (R)** | `xgb.train(params, xgb.DMatrix(x, label = y), nrounds)`; `xgb.cv()` for cross-validation and early stopping |
| **Main settings** | Learning rate, number of trees, depth, row and column sampling, minimum child weight, penalties |
| **Overfitting** | Too many trees overfit: choose the number of trees by cross-validation with early stopping |
| **Compare with** | A baseline model, and a random forest; judge on a test set with RMSE, MAE and $R^2$ |
| **Interpretation** | Gain and permutation importance; partial dependence; SHAP values with `predict(..., predcontrib = TRUE)` |
| **Cautions** | Sensitive to tuning; flat outside the range of the data; importance is not causation |
