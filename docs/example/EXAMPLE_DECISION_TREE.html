Description

This page reproduces the steps of rwf’s report_rtree() using rpart directly; both models are fit on the training part of the first of 10 folds created by rwf’s k_fold(). Installation instructions for rwf can be found here report_rtree() is not installed by default; it is in /rwf/working_functions/OTHER/ML_TREE_RPART.R

Theoretical Background

Recursive partitioning

rpart implements CART (Classification and Regression Trees, Breiman et al., 1984). Starting from the full dataset at the root node, the algorithm searches every predictor and every possible split point on that predictor, and picks the single split that most improves node purity. Each resulting child node is then split again, recursively, until a stopping rule is reached (a minimum number of observations per node, a minimum improvement threshold, or a maximum depth). The result is a binary tree: every internal node asks a yes/no question about one predictor, and every terminal node (“leaf”) gives a prediction.

Splitting criteria

The measure of “improvement” depends on the outcome type:

  • Classification (method = "class", used below for case) — by default rpart uses the Gini impurity of the class distribution within a node; a split is chosen to make the two child nodes as class-pure as possible.
  • Regression (method = "anova", used below for medv) — the criterion is the reduction in within-node sum of squares, i.e. the split that most reduces the variance of the outcome within each child node.

Cost-complexity pruning

A tree grown to full depth almost always overfits — it captures noise along with signal. rpart addresses this with cost-complexity pruning: every subtree \(T\) is scored as

\[R_\alpha(T) = R(T) + \alpha \, |T|\]

where \(R(T)\) is the tree’s error (relative to the root), \(|T|\) is the number of terminal nodes, and \(\alpha\) (called CP in rpart’s output) penalizes tree size. Varying \(\alpha\) from 0 to 1 produces a nested sequence of subtrees, from the grown tree (stopped at rpart’s default cp = 0.01) down to a single root node — this sequence is stored in model$cptable.

Cross-validated tree size

Because the apparent error of a tree always decreases as it grows (a larger tree can always fit the training data at least as well), rpart estimates each subtree’s error via internal k-fold cross-validation. cptable reports, for every candidate CP value: the relative error on the training data (rel error), the cross-validated error (xerror), and its standard deviation (xstd). The code below selects the tree whose CP gives the minimum xerror — a common, more conservative alternative is the “1-SE rule” (the smallest tree whose xerror is within one standard error of the minimum), which favors a simpler tree.

Variable importance

A predictor’s importance is the sum of the goodness-of-split (improvement in Gini impurity for classification, or in sum-of-squares for regression) for every split where it is the primary splitter, plus, for every split where it serves as a surrogate (a stand-in used when the primary splitting variable is missing), the primary split’s improvement weighted by the surrogate’s adjusted agreement. This is why a variable can show non-trivial importance even if it never appears as a labeled split in the final tree diagram.

Rpart Classification

The classification tree predicts case (secondary infertility, from the classic infert case-control study) from age, parity, education, spontaneous, and induced (prior abortions).

Growing and pruning the tree

rtree_classification was grown with rpart’s default stopping rules (cp = 0.01, minsplit = 20, minbucket = 7) in the create_models chunk above. Here it is pruned back to the CP value that minimizes the cross-validated error (xerror) in its cptable.

Code 
result<-data.frame(rtree_classification$cptable)
result$nsplit<-factor(result$nsplit+1)
minimun_size<-as.numeric(as.character(result[which.min(result[,"xerror"]),"nsplit"]))
initial_model<-rtree_classification
model<-rpart::prune(rtree_classification,
                    cp=rtree_classification$cptable[which.min(rtree_classification$cptable[,"xerror"]),"CP"])

plotcp() plots cross-validated relative error (xerror, with one-SE error bars) against CP (bottom axis) and tree size (top axis) — the dotted horizontal line marks one standard error above the minimum, the usual reference for the “1-SE rule”. rsq.rpart() prints the cptable and adds two more panels: apparent vs. cross-validated R-squared, and cross-validated relative error, against the number of splits. Because this is a classification tree, these values are 1 minus the relative misclassification error (relative to the root node’s error of 72/223), not explained variance, so read them as relative predictive error rather than a literal R²; rsq.rpart() itself warns that it “may not be applicable for this method”. Here cross-validated error drops only from 1.00 to 0.86 of the root error (about 28% vs 32% misclassification) and is lowest at the largest tree in the cptable, which is why the minimum-xerror rule keeps the full tree.

## Theoretical Background

### Recursive partitioning

`rpart` implements **CART** (Classification and Regression Trees, Breiman et al., 1984). Starting from the full dataset at the root node, the algorithm searches every predictor and every possible split point on that predictor, and picks the single split that most improves node purity. Each resulting child node is then split again, recursively, until a stopping rule is reached (a minimum number of observations per node, a minimum improvement threshold, or a maximum depth). The result is a **binary tree**: every internal node asks a yes/no question about one predictor, and every terminal node ("leaf") gives a prediction.

### Splitting criteria

The measure of "improvement" depends on the outcome type:

- **Classification** (`method = "class"`, used below for `case`) — by default `rpart` uses the **Gini impurity** of the class distribution within a node; a split is chosen to make the two child nodes as class-pure as possible.
- **Regression** (`method = "anova"`, used below for `medv`) — the criterion is the reduction in **within-node sum of squares**, i.e. the split that most reduces the variance of the outcome within each child node.

### Cost-complexity pruning

A tree grown to full depth almost always **overfits** — it captures noise along with signal. `rpart` addresses this with **cost-complexity pruning**: every subtree $T$ is scored as

$$R_\alpha(T) = R(T) + \alpha \, |T|$$

where $R(T)$ is the tree's error (relative to the root), $|T|$ is the number of terminal nodes, and $\alpha$ (called `CP` in `rpart`'s output) penalizes tree size. Varying $\alpha$ from 0 to 1 produces a nested sequence of subtrees, from the grown tree (stopped at `rpart`'s default `cp = 0.01`) down to a single root node — this sequence is stored in `model$cptable`.

### Cross-validated tree size

Because the *apparent* error of a tree always decreases as it grows (a larger tree can always fit the training data at least as well), `rpart` estimates each subtree's error via internal **k-fold cross-validation**. `cptable` reports, for every candidate `CP` value: the relative error on the training data (`rel error`), the cross-validated error (`xerror`), and its standard deviation (`xstd`). The code below selects the tree whose `CP` gives the **minimum `xerror`** — a common, more conservative alternative is the "1-SE rule" (the smallest tree whose `xerror` is within one standard error of the minimum), which favors a simpler tree.

### Variable importance

A predictor's importance is the sum of the goodness-of-split (improvement in Gini impurity for classification, or in sum-of-squares for regression) for every split where it is the *primary* splitter, plus, for every split where it serves as a **surrogate** (a stand-in used when the primary splitting variable is missing), the primary split's improvement weighted by the surrogate's adjusted agreement. This is why a variable can show non-trivial importance even if it never appears as a labeled split in the final tree diagram.

```{r create_models,include=TRUE}
infert_formula<-formula(factor(case)~age+parity+education+spontaneous+induced)
boston_formula<-formula(c("medv~",paste(names(MASS::Boston)[1:13],collapse="+")))
```

## Rpart Classification

The classification tree predicts `case` (secondary infertility, from the classic `infert` case-control study) from `age`, `parity`, `education`, `spontaneous`, and `induced` (prior abortions).

### Growing and pruning the tree

`rtree_classification` was grown with rpart's default stopping rules (`cp = 0.01`, `minsplit = 20`, `minbucket = 7`) in the `create_models` chunk above. Here it is pruned back to the `CP` value that minimizes the cross-validated error (`xerror`) in its `cptable`.

```{r classification_prune,echo=TRUE}
result<-data.frame(rtree_classification$cptable)

initial_model<-rtree_classification

                    cp=rtree_classification$cptable[which.min(rtree_classification$cptable[,"xerror"]),"CP"])
```

### Choosing the tree size via cross-validation

`plotcp()` plots cross-validated **relative error** (`xerror`, with one-SE error bars) against `CP` (bottom axis) and tree size (top axis) — the dotted horizontal line marks one standard error above the minimum, the usual reference for the "1-SE rule". `rsq.rpart()` prints the `cptable` and adds two more panels: apparent vs. cross-validated **R-squared**, and cross-validated **relative error**, against the number of splits. Because this is a *classification* tree, these values are 1 minus the relative misclassification error (relative to the root node's error of `r model$frame$dev[1]`/`r model$frame$n[1]`), not explained variance, so read them as relative predictive error rather than a literal R²; `rsq.rpart()` itself warns that it "may not be applicable for this method". Here cross-validated error drops only from 1.00 to `r round(min(model$cptable[,"xerror"]),2)` of the root error (about `r round(100*min(model$cptable[,"xerror"])*model$frame$dev[1]/model$frame$n[1])`% vs `r round(100*model$frame$dev[1]/model$frame$n[1])`% misclassification) and is lowest at the largest tree in the `cptable`, which is why the minimum-`xerror` rule keeps the full tree.
