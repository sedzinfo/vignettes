Simulating a CAT IRT using catR

This document is a practical exercise illustrating a Computerized Adaptive Testing (CAT) simulation. CAT is grounded in Item Response Theory (IRT) and requires prior estimation of item parameters. Its purpose is to deliver short, tailored questionnaires by selecting items from a pool in real time based on each respondent’s estimated ability. For example, if a participant answers a difficult item correctly, the algorithm skips easier items and instead presents a harder one to narrow down the ability estimate more efficiently. As a result, participants do not need to respond to every item in the pool. This simulation uses an item pool of 200 items with a maximum of 40 items administered per respondent. The catR package handles the simulation, while foreach and doSNOW are used for parallel computation.

Code 
library(catR)
library(foreach)
library(doSNOW)
library(ggplot2)
library(patchwork)

Simulate item pool

This simulation uses the 2PL (two-parameter logistic) model, which assigns two parameters to each item: a discrimination parameter (a), reflecting how well the item distinguishes between ability levels, and a difficulty parameter (b), reflecting how hard the item is. The genDichoMatrix function from catR generates item parameters for dichotomous (binary) items — items scored as either correct (1) or incorrect (0), such as multiple-choice questions.

The 200-item bank is generated with the following priors:

  • Parameter a follows a normal distribution with mean 2 and SD 0.1, ensuring all discrimination values are positive.
  • Parameter b follows a normal distribution with mean 0 and SD 4, producing items that span a wide range of difficulty — from very easy (large negative b) to very hard (large positive b).

A high a value means the item sharply differentiates between respondents near its difficulty level; a high b value means only respondents with high ability are likely to answer correctly.

genDichoMatrix also includes c (pseudo-guessing) and d (inattention) parameters. Since their values default to 0 and 1 respectively, they have no practical effect and the model reduces to a standard 2PL formulation.

Estimate parameters using a third package

Treating the simulated response matrix as real participant data (one row per respondent), the mirt package is used to estimate item parameters and respondent ability scores under the assumption that all items were administered. These full-information scores serve as a benchmark against the CAT estimates produced in the next step.

Code 
mirt_model<-mirt::mirt(data=data.frame(data),model=1,itemtype="2PL",technical=list(theta_lim=c(-6,6),NCYCLES=10000))

Simulate CAT administration and scoring

Each respondent is administered a CAT drawn from the 200-item pool, with a maximum of 40 items. The simulation is configured through four control lists:

  • start — defines first-item selection. The initial item is chosen to have a difficulty closest to θ = 0 (startSelect = "bOpt"), a neutral starting point before any ability information is available.
  • test — controls item selection and scoring during the adaptive phase. Ability is estimated using Bayesian Modal (BM) estimation (Birnbaum, 1969). Although EAP is generally the recommended estimator for unidimensional IRT, BM was found to yield scores highly correlated with the mirt EAP benchmark in this setup. Items are selected by bOpt, with a randomesque = 5 parameter introducing slight randomisation by sampling from the 5 most informative candidates. The estimation range is set to [−20, 20] to prevent ability estimates from collapsing at the boundaries.
  • final — specifies the scoring method applied at test termination (BM, same range).
  • stop — defines termination criteria. The test ends when either 40 items have been administered or the standard error of the provisional ability estimate drops below 0.3 — whichever occurs first.
Code 
start<-list(theta=0,nrItems=1,startSelect="bOpt")
test<-list(method="BM",itemSelect="bOpt",randomesque=5,range=c(-20,20))
final<-list(method="BM",range=c(-20,20))
stop<-list(rule=c("length","precision"),thr=c(40,0.3))
cl<-makeCluster(parallel::detectCores())
registerDoSNOW(cl)
result<-foreach(participant=1:nrow(data),.combine=rbind,.packages=c("catR")) %dopar% {
  rc_result<-randomCAT(itemBank=itemBank,
                       model=NULL,
                       responses=data[participant,],
                       start=start,
                       test=test,
                       stop=stop,
                       final=final)
  data.frame(questions=length(rc_result$thetaProv),
             est_theta=rc_result$thFinal,
             se=rc_result$seFinal)
  
}
stopCluster(cl)
result<-data.frame(result,mirt_scores=as.numeric(mirt::fscores(mirt_model)))

Results

The results are summarised graphically across six panels:

  • Plot 1 — CAT vs. mirt scores: Scatter plot of CAT ability estimates against mirt EAP scores. CAT respondents answered at most 40 items, while mirt scores are based on all 200 responses. High agreement between the two validates the adaptive procedure.
  • Plot 2 — Items administered vs. CAT theta: Respondents with ability estimates far from 0 (extreme thetas) tend to require more items before the precision criterion is met, because test information is lower in the tails of the ability distribution.
  • Plot 3 — Items administered vs. SE: Higher item counts are associated with elevated SE for two reasons: (1) the test was forced to stop at 40 items regardless of precision, and (2) extreme ability levels inherently have higher measurement error. Because extreme scores also require more items, both effects compound.
  • Plot 4 — CAT theta vs. SE: Standard error increases at the extremes of the ability scale — a direct consequence of lower test information in the tails. Recall that SE is approximately the inverse square root of the information function.
  • Plot 5 — Distribution of CAT estimated scores.
  • Plot 6 — Distribution of mirt estimated scores.

Conclusion

The distribution of estimated scores is approximately uniform, which is expected: the response-generation function sampled ability values evenly across the theta range, so all levels are equally represented. In a real-world scenario, ability scores tend to follow a roughly normal distribution, with most respondents clustered near the region of highest test information.

catR also provides simulateRespondents, a convenience function that runs a complete CAT simulation and computes summary diagnostics — bias, RMSE, and mean SE — as a function of true ability.

## Simulate CAT administration and scoring

Each respondent is administered a CAT drawn from the 200-item pool, with a maximum of 40 items. The simulation is configured through four control lists:

- **`start`** — defines first-item selection. The initial item is chosen to have a difficulty closest to θ = 0 (`startSelect = "bOpt"`), a neutral starting point before any ability information is available.
- **`test`** — controls item selection and scoring during the adaptive phase. Ability is estimated using Bayesian Modal (BM) estimation (Birnbaum, 1969). Although EAP is generally the recommended estimator for unidimensional IRT, BM was found to yield scores highly correlated with the `mirt` EAP benchmark in this setup. Items are selected by `bOpt`, with a `randomesque = 5` parameter introducing slight randomisation by sampling from the 5 most informative candidates. The estimation range is set to [−20, 20] to prevent ability estimates from collapsing at the boundaries.
- **`final`** — specifies the scoring method applied at test termination (BM, same range).
- **`stop`** — defines termination criteria. The test ends when either 40 items have been administered or the standard error of the provisional ability estimate drops below 0.3 — whichever occurs first.

```{r simulation,echo=TRUE,fig.align="center"}
start<-list(theta=0,nrItems=1,startSelect="bOpt")
test<-list(method="BM",itemSelect="bOpt",randomesque=5,range=c(-20,20))
final<-list(method="BM",range=c(-20,20))
stop<-list(rule=c("length","precision"),thr=c(40,0.3))
cl<-makeCluster(parallel::detectCores())
registerDoSNOW(cl)
result<-foreach(participant=1:nrow(data),.combine=rbind,.packages=c("catR")) %dopar% {
  rc_result<-randomCAT(itemBank=itemBank,
                       model=NULL,
                       responses=data[participant,],
                       start=start,
                       test=test,
                       stop=stop,
                       final=final)
  data.frame(questions=length(rc_result$thetaProv),
             est_theta=rc_result$thFinal,
             se=rc_result$seFinal)
  
}
stopCluster(cl)
result<-data.frame(result,mirt_scores=as.numeric(mirt::fscores(mirt_model)))
```
