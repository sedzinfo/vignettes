Isotonic Regression: Are the Bookmakers’ Probabilities Right?

  • Show All Code
  • Hide All Code
  • View Source
Isotonic regression in R with isoreg(), on the betting odds and results of 20,000 football matches in six countries: the best curve that never goes down, the pool-adjacent-violators algorithm by hand, weights and ties, the calibration of probabilities (reliability diagrams, the Brier score split into miscalibration, discrimination and uncertainty), consistency bands and tests by simulation, a comparison with logistic recalibration on later seasons, and APA reporting.

The question: a curve we know only one thing about

Before a football match a bookmaker offers odds. Odds of 2.00 for the home team mean: bet one euro, and get two back if it wins. So the bookmaker believes that the home team wins about half of the time. Every odd contains a probability.

Are these probabilities right? If we take all the matches in which the bookmaker said 60%, did the home team win 60% of them? And those with 20%, or 80%? We want the curve that turns the bookmaker’s probability into the true one.

We do not know the shape of that curve. It may bend anywhere. But we know one thing: it does not go down. A match with a higher implied probability cannot be a match with a smaller chance, or the bookmaker would not be in business.

Isotonic regression finds the best-fitting curve under this one condition. It needs no formula, no degree of a polynomial, no smoothing parameter. This page uses it for its most common modern job, checking and repairing probabilities, which is called calibration.

From odds to probabilities

Odds of \(o\) are fair if the probability is \(1/o\). But the three values of \(1/o\) (home, draw, away) add up to more than 1, and the excess is the bookmaker’s margin. The simplest correction divides by the sum:

\[p_{\text{home}} = \frac{1/o_{\text{home}}}{1/o_{\text{home}} + 1/o_{\text{draw}} + 1/o_{\text{away}}}\]

3. The model step by step, with formulas

Step 1: least squares with one condition

Sort the matches by their probability, \(p_1 \le p_2 \le \dots \le p_n\). We look for fitted values \(\mu_1, \dots, \mu_n\) that minimise the sum of squares,

\[\sum_i (y_i - \mu_i)^2 \qquad \text{subject to} \qquad \mu_1 \le \mu_2 \le \dots \le \mu_n\]

There are as many \(\mu\)’s as matches, and no formula that connects them. Only the order is imposed.

Step 2: the algorithm, pool adjacent violators

If the data are already in order, then \(\mu_i = y_i\) and we are done. If two neighbours are in the wrong order (the second is smaller than the first), they are violators. The best we can do for them is to make them equal, at their mean. Then look again: the new mean may violate the order with its own neighbours. Keep pooling until no violators are left. This is the pool-adjacent-violators algorithm, PAVA (Ayer et al., 1955):

Code 
pava <- function(y, w = rep(1, length(y)), trace = FALSE) {
  value <- numeric(0)
  weight <- numeric(0)
  size <- integer(0) # the blocks built so far
  for (i in seq_along(y)) {
    value <- c(value, y[i])
    weight <- c(weight, w[i])
    size <- c(size, 1L)
    # as long as the last block is below the one before it, pool the two into their weighted mean
    while (length(value) > 1 && value[length(value) - 1] >= value[length(value)]) {
      k <- length(value)
      value[k - 1] <- (weight[k - 1] * value[k - 1] + weight[k] * value[k]) /
        (weight[k - 1] + weight[k])
      weight[k - 1] <- weight[k - 1] + weight[k]
      size[k - 1] <- size[k - 1] + size[k]
      value <- value[-k]
      weight <- weight[-k]
      size <- size[-k]
    }
    if (trace) cat("after value", i, ":", format(rep(round(value, 2), size)), "\n")
  }
  rep(value, size)
}

toy <- c(1, 3, 2, 4, 3, 3, 7)

Follow it: the 3 and the 2 are in the wrong order, so both become 2.5. Then 4, 3 and 3 become 3.33. The result never goes down, and no other non-decreasing series is closer to the data.

Step 3: what the result looks like

The fit is a step function: flat blocks with jumps between them. Each block is the mean of the \(y\)’s in it, so blocks are bins, whose number and borders were chosen by the data. There is also an explicit formula, the max-min formula:

\[\hat\mu_i = \max_{s \le i}\; \min_{t \ge i}\; \text{mean}(y_s, \dots, y_t)\]

In words: the largest, over all starting points to the left, of the smallest mean that a block ending to the right can have.

Code 
max_min <- sapply(seq_along(toy), function(i)
  max(sapply(1:i, function(s) min(sapply(i:length(toy), function(t) mean(toy[s:t]))))))
rbind(pava = fit_toy, max_min = max_min)

Step 4: yes or no outcomes

Here \(y\) is 0 or 1, and the fitted values are probabilities. Least squares looks like the wrong criterion for that. But for isotonic regression it does not matter: the same fit also maximises the binomial likelihood, and it is the best for every other reasonable score (Barlow et al., 1972; Dimitriadis et al., 2021).

Step 5: ties and weights

Several matches with exactly the same \(p\) must get the same fitted value. We can replace them by one row with their mean, and the number of matches as its weight. PAVA with weights then takes weighted means, as in the code above.

Step 6: what is estimated, and how well

There is nothing to tune. The price is a slower convergence: the error of a smooth parametric curve shrinks with \(n^{-1/2}\), the error of an isotonic fit with \(n^{-1/3}\). Ten times the data halve the error. It is a method for large samples.

The curve is close to the diagonal, so the bookmaker is good. But it is not on it. Where the bookmaker says 15%, the home team won 12.3%; at 35%, 33.9%; at 65%, 67.1%; at 85%, 86.9%. The steps wobble (at 60% it won 58.2%), but on the whole the curve is steeper than the diagonal: home teams with low chances win less often than their odds say, and those with high chances more often. This is the well-known favourite–longshot bias of betting markets (Snowberg & Wolfers, 2010). Part of it may come from our way of removing the margin: we shrank the three probabilities in the same proportion, and bookmakers may put more of the margin on the outsiders.

5. Is it more than chance?

The fit has no standard errors. And a step function that follows the noise will never lie exactly on the diagonal, even if the probabilities are perfect. So we ask: what would the fit look like if the bookmaker were right? We can simulate that. Keep the probabilities, throw a new result for every match with exactly these probabilities, and fit again:

Code 
set.seed(7)
reps <- 500
grid <- seq(0.06, 0.90, by = 0.01)

  approx(p, isoreg(p, yy)$yf, xout = grid, method = "constant", rule = 2, ties = "ordered")$y
}

One number: the Brier score and its three parts

The Brier score is the mean squared difference between the probability and the result, \(\frac{1}{n}\sum (p_i - y_i)^2\). Smaller is better. Isotonic regression splits it into three parts that have a meaning (Dimitriadis et al., 2021):

\[\underbrace{\text{Brier}(p)}_{\text{the score}} = \underbrace{\text{Brier}(p) - \text{Brier}(\hat\mu)}_{\text{miscalibration}} - \underbrace{\big[\text{Brier}(\bar y) - \text{Brier}(\hat\mu)\big]}_{\text{discrimination}} + \underbrace{\text{Brier}(\bar y)}_{\text{uncertainty}}\]

  • Uncertainty is the score of the constant \(\bar y\), the share of home wins: how hard the matches are to predict without knowing anything.
  • Discrimination is how much better a perfectly recalibrated version of the probabilities would be: how well they sort the matches.
  • Miscalibration is what we lose because the numbers are not right.
Code 
decompose <- function(p, y) {
  o <- order(p)
  p <- p[o]
  y <- y[o]
  mu <- isoreg(p, y)$yf
  brier <- mean((p - y)^2)
  best <- mean((mu - y)^2)
  constant <- mean((mean(y) - y)^2)
  c(
    brier = brier,
    miscalibration = brier - best,
    discrimination = constant - best,
    uncertainty = constant
  )
}
all_matches <- decompose(p, y)
round(all_matches, 4)
         brier miscalibration discrimination    uncertainty 
        0.2067         0.0010         0.0408         0.2464

set.seed(8)

     observed mean_if_right             p 
 0.0009833516  0.0007232705  0.0039920160

The miscalibration is 0.0010. It is never zero, because the isotonic curve always fits a little better than the probabilities. If the bookmaker were right, it would be 0.0007 on average by chance alone. Only 1 of the 500 simulated values reached the observed one, p = .004. Compared with the discrimination of 0.0408 it is tiny: what limits the bookmaker is how unpredictable football is, not the calibration.

6. Repairing the probabilities

The fitted curve is also a recalibration: feed it a bookmaker’s probability and take the fitted value instead. To see if this helps, we must not judge it on the matches it was built from. Build it on eight seasons, and judge it on the last two:

Code 
train <- subset(matches, season %in% seasons[1:8])
test  <- subset(matches, season %in% seasons[9:10])

isotonic_fit <- function(d) {
  # returns a function: probability in, recalibrated probability out
  o <- order(d$p)

7. Things to keep in mind

  • The condition must come from knowledge, not from the data. Isotonic regression always returns a non-decreasing curve, also when the truth goes up and down. It cannot discover that the order is wrong. Use it only when the order is certain.
  • The ends are the weak point. The first and the last block are means of few cases, and they are pulled outwards: in a binary outcome they can be exactly 0 or 1. Do not trust the extremes, and do not take the logarithm of such a probability.
  • Steps are not real. The true curve is probably smooth. For predictions, straight lines between the block centres are better than jumps; for a smooth curve that does not go down, there are monotone splines (package scam).
  • In-sample fit is optimistic. The miscalibration measured with isotonic regression is positive even for perfect probabilities, so compare it with its value under simulation, as in section 5.
  • A decreasing relation: fit \(-y\) and change the sign. A single peak: increasing up to each candidate and decreasing after it (unimodal regression).
  • Other losses. gpava(..., solver = weighted.median) gives an isotonic median (compare quantile regression), and fractiles are available too.
  • Other predictors. Isotonic regression has one ordered predictor. For several, generalized additive models can force some of their curves to be monotone.
  • The matches are not all independent: the same teams play many times. The simulation treats them as independent given the probabilities.
  • Not a way to win. The bias is small next to the bookmaker’s margin. A bet of one euro on every home team would have lost money in every range of the odds:

## The question: a curve we know only one thing about

Before a football match a bookmaker offers **odds**. Odds of 2.00 for the home team mean: bet one euro, and get two back if it wins. So the bookmaker believes that the home team wins about half of the time. Every odd contains a **probability**.

Are these probabilities right? If we take all the matches in which the bookmaker said 60%, did the home team win 60% of them? And those with 20%, or 80%? We want the curve that turns the bookmaker's probability into the true one.

We do not know the shape of that curve. It may bend anywhere. But we know one thing: **it does not go down**. A match with a higher implied probability cannot be a match with a smaller chance, or the bookmaker would not be in business.

**Isotonic regression** finds the best-fitting curve under this one condition. It needs no formula, no degree of a polynomial, no smoothing parameter. This page uses it for its most common modern job, checking and repairing probabilities, which is called **calibration**.

### From odds to probabilities

Odds of $o$ are fair if the probability is $1/o$. But the three values of $1/o$ (home, draw, away) add up to more than 1, and the excess is the bookmaker's **margin**. The simplest correction divides by the sum:

$$p_{\text{home}} = \frac{1/o_{\text{home}}}{1/o_{\text{home}} + 1/o_{\text{draw}} + 1/o_{\text{away}}}$$

## 3. The model step by step, with formulas

### Step 1: least squares with one condition

Sort the matches by their probability, $p_1 \le p_2 \le \dots \le p_n$. We look for fitted values $\mu_1, \dots, \mu_n$ that minimise the sum of squares,

$$\sum_i (y_i - \mu_i)^2 \qquad \text{subject to} \qquad \mu_1 \le \mu_2 \le \dots \le \mu_n$$

There are as many $\mu$'s as matches, and no formula that connects them. Only the order is imposed.

### Step 2: the algorithm, pool adjacent violators

If the data are already in order, then $\mu_i = y_i$ and we are done. If two neighbours are in the wrong order (the second is smaller than the first), they are **violators**. The best we can do for them is to make them equal, at their mean. Then look again: the new mean may violate the order with its own neighbours. Keep pooling until no violators are left. This is the **pool-adjacent-violators algorithm**, PAVA (Ayer et al., 1955):

```{r pava}
pava <- function(y, w = rep(1, length(y)), trace = FALSE) {
  value <- numeric(0)
  weight <- numeric(0)
  size <- integer(0) # the blocks built so far
  for (i in seq_along(y)) {
    value <- c(value, y[i])
    weight <- c(weight, w[i])
    size <- c(size, 1L)
    # as long as the last block is below the one before it, pool the two into their weighted mean
    while (length(value) > 1 && value[length(value) - 1] >= value[length(value)]) {
      k <- length(value)
      value[k - 1] <- (weight[k - 1] * value[k - 1] + weight[k] * value[k]) /
        (weight[k - 1] + weight[k])
      weight[k - 1] <- weight[k - 1] + weight[k]
      size[k - 1] <- size[k - 1] + size[k]
      value <- value[-k]
      weight <- weight[-k]
      size <- size[-k]
    }
    if (trace) cat("after value", i, ":", format(rep(round(value, 2), size)), "\n")
  }
  rep(value, size)
}

toy <- c(1, 3, 2, 4, 3, 3, 7)
fit_toy <- pava(toy, trace = TRUE)
```

Follow it: the 3 and the 2 are in the wrong order, so both become 2.5. Then 4, 3 and 3 become 3.33. The result never goes down, and no other non-decreasing series is closer to the data.

### Step 3: what the result looks like

The fit is a **step function**: flat blocks with jumps between them. Each block is the mean of the $y$'s in it, so blocks are bins, whose number and borders were chosen by the data. There is also an explicit formula, the *max-min* formula:

$$\hat\mu_i = \max_{s \le i}\; \min_{t \ge i}\; \text{mean}(y_s, \dots, y_t)$$

In words: the largest, over all starting points to the left, of the smallest mean that a block ending to the right can have.

```{r max_min}
max_min <- sapply(seq_along(toy), function(i)
  max(sapply(1:i, function(s) min(sapply(i:length(toy), function(t) mean(toy[s:t]))))))
rbind(pava = fit_toy, max_min = max_min)
```

### Step 4: yes or no outcomes

Here $y$ is 0 or 1, and the fitted values are probabilities. Least squares looks like the wrong criterion for that. But for isotonic regression it does not matter: the same fit **also maximises the binomial likelihood**, and it is the best for every other reasonable score (Barlow et al., 1972; Dimitriadis et al., 2021).

### Step 5: ties and weights

Several matches with exactly the same $p$ must get the same fitted value. We can replace them by one row with their mean, and the number of matches as its **weight**. PAVA with weights then takes weighted means, as in the code above.

### Step 6: what is estimated, and how well

There is nothing to tune. The price is a slower convergence: the error of a smooth parametric curve shrinks with $n^{-1/2}$, the error of an isotonic fit with $n^{-1/3}$. Ten times the data halve the error. It is a method for large samples.

## 5. Is it more than chance?

The fit has no standard errors. And a step function that follows the noise will never lie exactly on the diagonal, even if the probabilities are perfect. So we ask: **what would the fit look like if the bookmaker were right?** We can simulate that. ### One number: the Brier score and its three parts

The **Brier score** is the mean squared difference between the probability and the result, $\frac{1}{n}\sum (p_i - y_i)^2$. Smaller is better. Isotonic regression splits it into three parts that have a meaning (Dimitriadis et al., 2021):

$$\underbrace{\text{Brier}(p)}_{\text{the score}} = \underbrace{\text{Brier}(p) - \text{Brier}(\hat\mu)}_{\text{miscalibration}} - \underbrace{\big[\text{Brier}(\bar y) - \text{Brier}(\hat\mu)\big]}_{\text{discrimination}} + \underbrace{\text{Brier}(\bar y)}_{\text{uncertainty}}$$

- **Uncertainty** is the score of the constant $\bar y$, the share of home wins: how hard the matches are to predict without knowing anything.
- **Discrimination** is how much better a perfectly recalibrated version of the probabilities would be: how well they **sort** the matches.
- **Miscalibration** is what we lose because the numbers are not right.

```{r decomposition}
decompose <- function(p, y) {
  o <- order(p)
  p <- p[o]
  y <- y[o]
  mu <- isoreg(p, y)$yf
  brier <- mean((p - y)^2)
  best <- mean((mu - y)^2)
  constant <- mean((mean(y) - y)^2)
  c(
    brier = brier,
    miscalibration = brier - best,
    discrimination = constant - best,
    uncertainty = constant
  )
}
all_matches <- decompose(p, y)
round(all_matches, 4)

set.seed(8)
null_mcb <- replicate(500, { yy <- rbinom(length(p), 1, p); decompose(p, yy)[["miscalibration"]] })
p_mcb <- mean(c(null_mcb, all_matches[["miscalibration"]]) >= all_matches[["miscalibration"]])
c(observed = all_matches[["miscalibration"]], mean_if_right = mean(null_mcb), p = p_mcb)
```

The miscalibration is `r f4(all_matches[["miscalibration"]])`. It is **never zero**, because the isotonic curve always fits a little better than the probabilities. If the bookmaker were right, it would be `r f4(mean(null_mcb))` on average by chance alone. Only `r sum(null_mcb >= all_matches[["miscalibration"]])` of the 500 simulated values reached the observed one, *p* `r pval(p_mcb)`. Compared with the discrimination of `r f4(all_matches[["discrimination"]])` it is tiny: what limits the bookmaker is how unpredictable football is, not the calibration.

## 6. Repairing the probabilities

The fitted curve is also a **recalibration**: feed it a bookmaker's probability and take the fitted value instead. To see if this helps, we must not judge it on the matches it was built from. Build it on eight seasons, and judge it on the last two:

```{r recalibration}
train <- subset(matches, season %in% seasons[1:8])
test  <- subset(matches, season %in% seasons[9:10])

isotonic_fit <- function(d) {
  # returns a function: probability in, recalibrated probability out
  o <- order(d$p)
  mu <- isoreg(d$p, d$y)$yf
  # straight lines between the points
  function(q) approx(d$p[o], mu, xout = q, rule = 2, ties = mean)$y
}
logit <- function(q) log(q / (1 - q))
logistic_fit <- function(d) {
  # logistic regression of the result on the logit of the probability
  m <- glm(y ~ logit(p), family = binomial, data = d)
  function(q) unname(predict(m, data.frame(p = q), type = "response"))
}
brier <- function(q, y) mean((q - y)^2)
judge <- function(tr, te) c(matches = nrow(te),
                            bookmaker = brier(te$p, te$y),
                            isotonic  = brier(isotonic_fit(tr)(te$p), te$y),
                            logistic  = brier(logistic_fit(tr)(te$p), te$y))
repair <- rbind(
  `all six countries` = judge(train, test),
  `Greece only` = judge(subset(train, country == "Greece"), subset(test, country == "Greece"))
)
round(repair, 4)

# is the gain more than luck? the change of the squared error, match by match, with its standard
# error
gain <- function(tr, te, method) {
  change <- (method(tr)(te$p) - te$y)^2 - (te$p - te$y)^2
  c(change = mean(change), SE = sd(change) / sqrt(length(change)))
}
gains <- rbind(
  all_isotonic = gain(train, test, isotonic_fit),
  all_logistic = gain(train, test, logistic_fit),
  greece_isotonic = gain(
    subset(train, country == "Greece"),
    subset(test, country == "Greece"),
    isotonic_fit
  ),
  greece_logistic = gain(
    subset(train, country == "Greece"),
    subset(test, country == "Greece"),
    logistic_fit
  )
)
round(gains, 5)

logit_coefs <- coef(glm(y ~ logit(p), family = binomial, data = train))
logit_coefs
```

**Logistic recalibration** (also known as Platt scaling) assumes a shape: a straight line between the logit of the bookmaker's probability and the logit of the true one, with two parameters. Its slope is `r f2(logit_coefs[[2]])`, above 1: the probabilities should be spread further apart.

- For all the matches, the Brier score on the two later seasons goes from `r f4(repair[1, "bookmaker"])` to `r f4(repair[1, "isotonic"])` with isotonic regression and `r f4(repair[1, "logistic"])` with the logistic curve.
- For Greece alone, from `r f4(repair[2, "bookmaker"])` to `r f4(repair[2, "isotonic"])` and `r f4(repair[2, "logistic"])`.

The gains are tiny, as the decomposition promised: there was little miscalibration to remove. For all the matches, isotonic regression gained `r formatC(-gains["all_isotonic", "change"], format = "f", digits = 5)` with a standard error of `r formatC(gains["all_isotonic", "SE"], format = "f", digits = 5)`, and the logistic curve `r formatC(-gains["all_logistic", "change"], format = "f", digits = 5)` with a standard error of `r formatC(gains["all_logistic", "SE"], format = "f", digits = 5)`. The gains are alike in size, but that of the logistic curve is steadier: it moves every probability a little, while the isotonic curve moves them in jumps. In Greece the `r num(repair[2, "matches"])` matches of the last two seasons are too few to say anything. In general, isotonic regression needs thousands of cases, because with few it follows the noise; it wins when the true shape is not what the parametric curve assumes (Niculescu-Mizil & Caruana, 2005).

## 7. Things to keep in mind

- **The condition must come from knowledge, not from the data.** Isotonic regression always returns a non-decreasing curve, also when the truth goes up and down. It cannot discover that the order is wrong. Use it only when the order is certain.
- **The ends are the weak point.** The first and the last block are means of few cases, and they are pulled outwards: in a binary outcome they can be exactly 0 or 1. Do not trust the extremes, and do not take the logarithm of such a probability.
- **Steps are not real.** The true curve is probably smooth. For predictions, straight lines between the block centres are better than jumps; for a smooth curve that does not go down, there are monotone splines (package `scam`).
- **In-sample fit is optimistic.** The miscalibration measured with isotonic regression is positive even for perfect probabilities, so compare it with its value under simulation, as in section 5.
- **A decreasing relation**: fit $-y$ and change the sign. **A single peak**: increasing up to each candidate and decreasing after it (unimodal regression).
- **Other losses.** `gpava(..., solver = weighted.median)` gives an isotonic **median** (compare [quantile regression](EXAMPLE_QUANTILE_REGRESSION.Rmd)), and fractiles are available too.
- **Other predictors.** Isotonic regression has one ordered predictor. For several, generalized additive models can force some of their curves to be monotone.
- **The matches are not all independent**: the same teams play many times. The simulation treats them as independent given the probabilities.
- **Not a way to win.** The bias is small next to the bookmaker's margin. A bet of one euro on every home team would have lost money in every range of the odds:

```{r returns}
matches$return <- matches$odds_home * matches$y - 1
ranges <- cut(matches$p, c(0, 0.2, 0.4, 0.6, 0.8, 1))
round(tapply(matches$return, ranges, mean), 3)      # euros won per euro
```

**Method** (data analysis):

> We compared the odds of one bookmaker with the results of `r num(nrow(matches))` first-division football matches in six countries, seasons 2015–16 to 2024–25. The odds were converted to probabilities by dividing their reciprocals by their sum. We estimated the probability of a home win as a non-decreasing function of the implied probability with isotonic regression (pool-adjacent-violators algorithm; de Leeuw et al., 2009), which is justified because a higher implied probability should not go with a lower chance of winning. Tied probabilities were pooled. ## 9. Summary

| | |
|---|---|
| **When** | The relation can only go up (or only down), and its shape is unknown |
| **The model** | Minimise $\sum w_i (y_i - \mu_i)^2$ subject to $\mu_1 \le \dots \le \mu_n$ |
| **The algorithm** | Pool adjacent violators: replace neighbours in the wrong order by their mean, until none are left |
| **How (R)** | `isoreg(x, y)`; with weights or medians, `isotone::gpava(z, y, weights, solver)` |
| **The result** | A step function; every step is the mean of a block chosen by the data |
| **Binary outcome** | The same fit maximises the likelihood |
| **Uses** | Calibration of probabilities, dose and response, growth, ordered categories |
| **Uncertainty** | Simulation under calibration, or the bootstrap |
| **Weak points** | The ends, small samples, and an order that is not true |
| **Related pages** | [Logistic regression with a rare outcome](EXAMPLE_IMBALANCED_LOGISTIC.Rmd) (calibration), [quantile regression](EXAMPLE_QUANTILE_REGRESSION.Rmd) |
