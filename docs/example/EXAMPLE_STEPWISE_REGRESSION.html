Stepwise Regression: Which Body Measurements Predict Body Fat?

  • Show All Code
  • Hide All Code
  • View Source
Stepwise regression in R with step(), on body fat measured under water in 250 men and 13 tape measurements: forward, backward and both directions, AIC, BIC and p values by hand, all subsets, and why it is risky: findings in shuffled data, unstable choices under the bootstrap, inflated coefficients, optimistic fit, with cross-validation against the full model, lasso and ridge, and APA reporting.

The question: which measurements should we keep?

The accurate way to measure a man’s body fat is to weigh him under water: fat floats, muscle and bone sink. It needs a tank and takes time. A tape measure costs nothing. So we would like a formula that predicts the percentage of body fat from measurements that anyone can take: neck, chest, abdomen, hip, thigh and so on.

There are 13 candidates. Do we need all of them? Stepwise regression lets the computer choose: it adds the predictor that helps most, or removes the one that helps least, and repeats until nothing improves.

It is one of the most used methods of data analysis, and one of the most criticised (Harrell, 2015; Smith, 2018). This page does both things. It shows how the method works, step by step, and then it tests it: on the same data, on shuffled data, on resampled data, and against simpler alternatives.

3. The method step by step, with formulas

Step 1: the trade-off

Every predictor that is added lowers the sum of squared residuals, the RSS, even a column of random numbers. So a criterion must put a price on each predictor. The usual one is Akaike’s information criterion. For a linear regression with \(k\) estimated coefficients,

\[\text{AIC} = n \log\!\left(\frac{\text{RSS}}{n}\right) + 2k\]

The smaller the better: the first part rewards fit, and each coefficient costs 2. The BIC charges \(\log(n)\) per coefficient instead of 2. With \(n\) = 250 that is 5.52, so BIC keeps fewer predictors.

Step 2: one step forward

Start with no predictor. Try each of the 13 alone, and take the one with the smallest AIC:

Code 
n <- nrow(men)
aic_of <- function(vars) {                     # AIC of the model with these predictors
  fit <- lm(reformulate(if (length(vars)) vars else "1", "fat"), data = men)
  n * log(sum(resid(fit)^2) / n) + 2 * length(coef(fit))
}
first <- sapply(predictors, function(v) aic_of(v))

chosen <- character(0)
path <- data.frame(step = 0, added = "(none)", AIC = aic_of(chosen))
repeat {
  left  <- setdiff(predictors, chosen)
  tries <- sapply(left, function(v) aic_of(c(chosen, v)))
  if (!length(left) || min(tries) >= tail(path$AIC, 1)) break    # nothing improves: stop
  chosen <- c(chosen, names(which.min(tries)))
  path   <- rbind(path, data.frame(step = nrow(path), added = tail(chosen, 1), AIC = min(tries)))
}

Step 3: backward, and both ways

Backward elimination starts from the model with all 13 and removes, one at a time, the predictor whose removal lowers the AIC most. Both directions is forward selection that checks, after each addition, whether an earlier predictor can now go.

Step 4: what AIC means as a p value

Removing one predictor is an improvement if the AIC falls, that is if the likelihood-ratio statistic of that predictor is below 2. In a large sample this statistic follows a \(\chi^2\) distribution with 1 degree of freedom, so

\[\text{AIC keeps a predictor when } p < P(\chi^2_1 > 2) = .157\]

and BIC, with \(n = 250\), when \(p < P(\chi^2_1 > \log n) = .019\). The old versions of stepwise regression used p values directly, with “\(F\) to enter” and “\(F\) to remove”. All of them are the same idea with a different price.

Step 5: how many models are we choosing from?

With 13 candidates there are \(2^{13}\) = 8,192 possible models. Stepwise looks at a small part of them, and reports the winner as if it had been the only one.

5. Testing the method

Test 1: an outcome with no relation to anything

We shuffle the body-fat column. Now each man has the body fat of another man, and all 13 predictors are useless by construction. A good method should come back empty-handed:

Code 
set.seed(2026)
shuffled <- t(replicate(500, {
  fake     <- men
  fake$fat <- sample(fake$fat)
  m  <- step(lm(fat ~ ., data = fake), trace = 0)
  s  <- summary(m)
  p  <- s$coefficients[-1, 4]
  fs <- s$fstatistic
  c(kept        = length(p),
    significant = sum(p < .05),
    R2          = s$r.squared,
    p_model     = if (length(p)) pf(fs[[1]], fs[[2]], fs[[3]], lower.tail = FALSE) else 1)

In 500 shuffled data sets, backward elimination kept 2.9 predictors on average. In 73% of them at least one had p < .05, and in 53% the F test of the whole model was significant, where the promise is 5%. This is known as Freedman’s paradox (Freedman, 1983): screen many noise variables, refit with the survivors, and the final model looks convincing.

Test 3: are the coefficients right?

A predictor with a weak effect gets in when, by luck, its effect looks strong in the sample. So among the selected, weak effects are overestimated (the “winner’s curse”). To see this we need to know the truth, so we make one: new body-fat values that follow the full model exactly, with its coefficients and its residual spread.

Test 4: is the fit as good as it looks?

The \(R^2\) of a chosen model is too good, because the choice and the fit used the same men. Cross-validation measures honestly: hide a tenth of the men, do everything on the rest, predict the hidden ones. The word everything is important. If the predictors are chosen on all the men first and only the fit is cross-validated, the hidden men have already helped to choose, and the result is still too good.

Code 
set.seed(2029)
cv_once <- function() {
  fold <- sample(rep(1:10, length.out = nrow(men)))
  pred <- matrix(
    NA,
    nrow(men),
    8,
    dimnames = list(
      NULL,
      c("full", "backward", "chosen_before", "bic", "abdomen", "abdomen_weight", "lasso", "ridge")
    )
  )
  for (k in 1:10) {
    train <- men[fold != k, ]
    test <- men[fold == k, ]
    x <- as.matrix(train[, predictors])
    xt <- as.matrix(test[, predictors])
    m <- lm(fat ~ ., data = train)
    out <- list(
      m,
      step(m, trace = 0), # selection inside the fold: honest
      lm(formula(backward), data = train), # predictors chosen on all men: cheating
      step(m, trace = 0, k = log(nrow(train))),
      lm(fat ~ abdomen, data = train),
      lm(fat ~ abdomen + weight, data = train)
    )

6. What to do instead

Your aim Do this
Explain: test a theory, estimate an effect Choose the predictors from theory before you look. Fit that model, report it, whatever the p values. Dropping a confounder because p > .05 does not make it harmless
Predict, with enough data Keep the full model, or shrink it: ridge, lasso or elastic net (see regularized regression)
Predict, many correlated predictors Principal components or partial least squares regression
A short formula for practical use Choose from the cost of the measurements first. If you must select by data, use backward elimination with AIC, report the bootstrap frequencies, shrink the coefficients, and validate with the selection inside the cross-validation
Explore Use whatever you like, and call it exploration. The test is the next data set

Two predictors, abdomen and weight, do almost as well as anything. This is the usual result with correlated predictors: many models are equally good, and which of them you use is a matter of convenience. What you cannot do is to say that the predictors that were left out do not matter.

Is the choice of predictors in blocks, planned before, stepwise regression? No. That is hierarchical regression: the order comes from the theory, and the p values mean what they say.

7. Things to keep in mind

  • The p values of a selected model are not p values. They ignore the search. There are corrections for some procedures (post-selection inference; Taylor & Tibshirani, 2015), but the ordinary output of summary() is not one of them.
  • “Not selected” does not mean “no effect”. Weight was not selected by backward elimination, although it correlates at .61 with body fat: its information was already in the other measurements.
  • The starting point matters. Backward elimination from the full model is usually preferred to forward selection, because it judges every predictor next to all the others (Heinze et al., 2018). It needs a full model that can be fitted: at the very least more rows than predictors, better 10 to 20 rows per candidate. Here there are 19.2.
  • Count the candidates, not the survivors. A model with 3 predictors chosen among 50 has the overfitting of a much larger model.
  • Whole factors. A factor with four levels is three columns that belong together: step() keeps or drops them together. Interactions should not stay without their main effects; step() respects that too.
  • Missing values. Adding a predictor with missing values changes the rows that are used, and the AICs are then not comparable. Decide on the rows first (or impute, see missing data).
  • The odd rows matter. We dropped two men and corrected one. With unstable selection a single unusual row can change the chosen set, so check influence before you select.

## The question: which measurements should we keep?

The accurate way to measure a man's body fat is to weigh him **under water**: fat floats, muscle and bone sink. It needs a tank and takes time. A tape measure costs nothing. So we would like a formula that predicts the percentage of body fat from measurements that anyone can take: neck, chest, abdomen, hip, thigh and so on.

There are 13 candidates. Do we need all of them? **Stepwise regression** lets the computer choose: it adds the predictor that helps most, or removes the one that helps least, and repeats until nothing improves.

It is one of the most used methods of data analysis, and one of the most criticised (Harrell, 2015; Smith, 2018). This page does both things. It shows how the method works, step by step, and then it **tests** it: on the same data, on shuffled data, on resampled data, and against simpler alternatives.

## 3. The method step by step, with formulas

### Step 1: the trade-off

Every predictor that is added lowers the sum of squared residuals, the **RSS**, even a column of random numbers. So a criterion must put a **price** on each predictor. The usual one is Akaike's information criterion. For a linear regression with $k$ estimated coefficients,

$$\text{AIC} = n \log\!\left(\frac{\text{RSS}}{n}\right) + 2k$$

The smaller the better: the first part rewards fit, and each coefficient costs 2. The BIC charges $\log(n)$ per coefficient instead of 2. With $n$ = `r nrow(men)` that is `r f2(log(nrow(men)))`, so BIC keeps fewer predictors.

### Step 2: one step forward

Start with no predictor. Try each of the 13 alone, and take the one with the smallest AIC:

```{r step_by_hand}
n <- nrow(men)
aic_of <- function(vars) {                     # AIC of the model with these predictors
  fit <- lm(reformulate(if (length(vars)) vars else "1", "fat"), data = men)
  n * log(sum(resid(fit)^2) / n) + 2 * length(coef(fit))
}
first <- sapply(predictors, function(v) aic_of(v))
c(none = aic_of(character(0)), head(sort(first), 4))
```

The abdomen wins by a wide margin. Keep it, try each of the other 12 next to it, and continue:

```{r forward_by_hand}
chosen <- character(0)
path <- data.frame(step = 0, added = "(none)", AIC = aic_of(chosen))
repeat {
  left  <- setdiff(predictors, chosen)
  tries <- sapply(left, function(v) aic_of(c(chosen, v)))
  if (!length(left) || min(tries) >= tail(path$AIC, 1)) break    # nothing improves: stop
  chosen <- c(chosen, names(which.min(tries)))
  path   <- rbind(path, data.frame(step = nrow(path), added = tail(chosen, 1), AIC = min(tries)))
}
path
```

Forward selection stops after `r length(chosen)` predictors.

### Step 3: backward, and both ways

**Backward elimination** starts from the model with all 13 and removes, one at a time, the predictor whose removal lowers the AIC most. **Both directions** is forward selection that checks, after each addition, whether an earlier predictor can now go.

### Step 4: what AIC means as a *p* value

Removing one predictor is an improvement if the AIC falls, that is if the likelihood-ratio statistic of that predictor is below 2. In a large sample this statistic follows a $\chi^2$ distribution with 1 degree of freedom, so

$$\text{AIC keeps a predictor when } p < P(\chi^2_1 > 2) = `r nz(pchisq(2, 1, lower.tail = FALSE), 3)`$$

and BIC, with $n = `r nrow(men)`$, when $p < P(\chi^2_1 > \log n) = `r nz(pchisq(log(nrow(men)), 1, lower.tail = FALSE), 3)`$. The old versions of stepwise regression used *p* values directly, with "$F$ to enter" and "$F$ to remove". All of them are the same idea with a different price.

### Step 5: how many models are we choosing from?

With 13 candidates there are $2^{13}$ = `r num(2^13)` possible models. Stepwise looks at a small part of them, and reports the winner as if it had been the only one.

## 5. Testing the method

### Test 1: an outcome with no relation to anything

We **shuffle** the body-fat column. Now each man has the body fat of another man, and all 13 predictors are useless by construction. A good method should come back empty-handed:

```{r shuffle}
set.seed(2026)
shuffled <- t(replicate(500, {
  fake     <- men
  fake$fat <- sample(fake$fat)
  m  <- step(lm(fat ~ ., data = fake), trace = 0)
  s  <- summary(m)
  p  <- s$coefficients[-1, 4]
  fs <- s$fstatistic
  c(kept        = length(p),
    significant = sum(p < .05),
    R2          = s$r.squared,
    p_model     = if (length(p)) pf(fs[[1]], fs[[2]], fs[[3]], lower.tail = FALSE) else 1)
}))
colMeans(shuffled[, 1:3])
c(
  any_significant = mean(shuffled[, "significant"] > 0),
  model_significant = mean(shuffled[, "p_model"] < .05)
)
```

In 500 shuffled data sets, backward elimination kept `r f1(mean(shuffled[, "kept"]))` predictors on average. In `r pct(mean(shuffled[, "significant"] > 0))` of them at least one had *p* < .05, and in `r pct(mean(shuffled[, "p_model"] < .05))` the *F* test of the whole model was significant, where the promise is 5%. This is known as **Freedman's paradox** (Freedman, 1983): screen many noise variables, refit with the survivors, and the final model looks convincing.

Only `r sum(frequency > .9)` predictors, `r paste(names(frequency)[frequency > .9], collapse = " and ")`, are chosen nearly always. Most of the others are a coin toss. The 1,000 samples produced **`r num(n_models)` different models**; the most common one came up `r max(table(as_text))` times, and the model that backward elimination chose in our data only `r sum(as_text == our_model)` times. A statement such as "the predictors of body fat are age, height, neck, chest, abdomen, forearm and wrist" is a statement about this sample.

### Test 3: are the coefficients right?

A predictor with a weak effect gets in when, by luck, its effect looks strong in the sample. So among the selected, weak effects are **overestimated** (the "winner's curse"). To see this we need to know the truth, so we make one: new body-fat values that follow the full model exactly, with its coefficients and its residual spread.

```{r winners_curse}
set.seed(2028)
truth <- coef(full)
sims  <- 1000
estimates <- matrix(NA, sims, length(predictors), dimnames = list(NULL, predictors))
for (i in seq_len(sims)) {
  new     <- men
  new$fat <- fitted(full) + rnorm(nrow(men), 0, sigma(full))
  b <- coef(step(lm(fat ~ ., data = new), trace = 0))
  estimates[i, intersect(names(b), predictors)] <- b[intersect(names(b), predictors)]
}
curse <- data.frame(predictor = predictors, true = truth[predictors],
                    selected = colMeans(!is.na(estimates)),
                    mean_when_selected = colMeans(estimates, na.rm = TRUE))
curse$ratio <- curse$mean_when_selected / curse$true
curse <- curse[order(-curse$selected), ]
print(data.frame(predictor = curse$predictor, round(curse[, -1], 2)), row.names = FALSE)
```

```{r winners_numbers}
curse_of <- function(v, col) curse[curse$predictor == v, col]
```

The abdomen and the wrist are nearly always selected, and their average estimate is close to the truth. The forearm has a true coefficient of `r f2(curse_of("forearm", "true"))`; it is selected in `r pct(curse_of("forearm", "selected"))` of the samples, and then its average estimate is `r f2(curse_of("forearm", "mean_when_selected"))`, `r f1(curse_of("forearm", "ratio"))` times too large. (For the predictors that are strongly correlated with others, such as weight and hip, the coefficient also changes meaning when the others are left out, so the ratio mixes two things.)

### Test 4: is the fit as good as it looks?

The $R^2$ of a chosen model is too good, because the choice and the fit used the same men. **Cross-validation** measures honestly: hide a tenth of the men, do **everything** on the rest, predict the hidden ones. The word *everything* is important. If the predictors are chosen on all the men first and only the fit is cross-validated, the hidden men have already helped to choose, and the result is still too good.

```{r cross_validation}
set.seed(2029)
cv_once <- function() {
  fold <- sample(rep(1:10, length.out = nrow(men)))
  pred <- matrix(
    NA,
    nrow(men),
    8,
    dimnames = list(
      NULL,
      c("full", "backward", "chosen_before", "bic", "abdomen", "abdomen_weight", "lasso", "ridge")
    )
  )
  for (k in 1:10) {
    train <- men[fold != k, ]
    test <- men[fold == k, ]
    x <- as.matrix(train[, predictors])
    xt <- as.matrix(test[, predictors])
    m <- lm(fat ~ ., data = train)
    out <- list(
      m,
      step(m, trace = 0), # selection inside the fold: honest
      lm(formula(backward), data = train), # predictors chosen on all men: cheating
      step(m, trace = 0, k = log(nrow(train))),
      lm(fat ~ abdomen, data = train),
      lm(fat ~ abdomen + weight, data = train)
    )
    pred[fold == k, 1:6] <- sapply(out, predict, newdata = test)
    pred[fold == k, 7] <- predict(cv.glmnet(x, train$fat, alpha = 1), xt, s = "lambda.min")
    pred[fold == k, 8] <- predict(cv.glmnet(x, train$fat, alpha = 0), xt, s = "lambda.min")
  }
  sqrt(colMeans((pred - men$fat)^2))
}
rmse <- rowMeans(replicate(20, cv_once()))          # 20 random splits, averaged
cbind(rmse)
apparent <- sqrt(mean(resid(backward)^2)) # the same men used for choosing, fitting and judging
apparent
```

## 6. What to do instead

| Your aim | Do this |
|---|---|
| **Explain**: test a theory, estimate an effect | Choose the predictors from theory before you look. Fit that model, report it, whatever the *p* values. Dropping a confounder because *p* > .05 does not make it harmless |
| **Predict**, with enough data | Keep the full model, or shrink it: ridge, lasso or elastic net (see [regularized regression](EXAMPLE_REGULARIZED_REGRESSION.Rmd)) |
| **Predict**, many correlated predictors | [Principal components](EXAMPLE_PRINCIPAL_COMPONENTS_REGRESSION.Rmd) or [partial least squares](EXAMPLE_PARTIAL_LEAST_SQUARES.Rmd) regression |
| **A short formula** for practical use | Choose from the cost of the measurements first. If you must select by data, use backward elimination with AIC, report the bootstrap frequencies, shrink the coefficients, and validate with the selection **inside** the cross-validation |
| **Explore** | Use whatever you like, and call it exploration. The test is the next data set |

Two predictors, abdomen and weight, do almost as well as anything. This is the usual result with correlated predictors: many models are equally good, and which of them you use is a matter of convenience. What you cannot do is to say that the predictors that were left out do not matter.

Is the choice of predictors **in blocks, planned before**, stepwise regression? No. That is [hierarchical regression](EXAMPLE_HIERARCHICAL_REGRESSION.Rmd): the order comes from the theory, and the *p* values mean what they say.

## 7. Things to keep in mind

- **The *p* values of a selected model are not *p* values.** They ignore the search. There are corrections for some procedures (post-selection inference; Taylor & Tibshirani, 2015), but the ordinary output of `summary()` is not one of them.
- **"Not selected" does not mean "no effect".** Weight was not selected by backward elimination, although it correlates at `r nz(cors["fat", "weight"])` with body fat: its information was already in the other measurements.
- **The starting point matters.** Backward elimination from the full model is usually preferred to forward selection, because it judges every predictor next to all the others (Heinze et al., 2018). It needs a full model that can be fitted: at the very least more rows than predictors, better 10 to 20 rows per candidate. Here there are `r f1(nrow(men) / 13)`.
- **Count the candidates, not the survivors.** A model with 3 predictors chosen among 50 has the overfitting of a much larger model.
- **Whole factors.** A factor with four levels is three columns that belong together: `step()` keeps or drops them together. Interactions should not stay without their main effects; `step()` respects that too.
- **Missing values.** Adding a predictor with missing values changes the rows that are used, and the AICs are then not comparable. Decide on the rows first (or impute, see [missing data](EXAMPLE_MISSING_DATA.Rmd)).
- **The odd rows matter.** We dropped two men and corrected one. With unstable selection a single unusual row can change the chosen set, so check [influence](EXAMPLE_ROBUST_REGRESSION.Rmd) before you select.

If you use selection, the report (APA 7th edition) must let the reader judge it: all the candidates, the algorithm and its criterion, the stability, and an honest estimate of the error. The numbers come from the R objects:

**Method** (data analysis):

> We developed a formula for percentage of body fat, measured by underwater weighing, in `r nrow(men)` men (Johnson, 1996), after correcting one height that was a typing error and excluding one man with an impossible value of 0% and one man of `r f1(raw$weight[39] * 0.45359237)` kg. The candidates were age, weight, height and 10 circumferences (13 in all; `r f1(nrow(men) / 13)` men per candidate). We used backward elimination with the AIC, starting from the model with all the candidates. Stability was assessed with 1,000 bootstrap samples, and prediction error with 10-fold cross-validation, repeated 20 times, in which the selection was repeated in every fold. Analyses were conducted in R (Version `r paste(R.version$major, R.version$minor, sep = ".")`; R Core Team, `r R.version$year`).

**Results:**

> Backward elimination kept `r length(vars_of(backward))` of the 13 candidates (Table 1), *R*² = `r nz(summary(backward)$r.squared)` (full model: *R*² = `r nz(summary(full)$r.squared)`). Only `r paste(names(frequency)[frequency > .9], collapse = " and ")` were selected in more than 90% of the bootstrap samples; the 1,000 samples gave `r num(n_models)` different models, and the model in Table 1 was chosen in `r sum(as_text == our_model)` of them. The cross-validated prediction error was `r f2(rmse[["backward"]])` percentage points (`r f2(apparent)` in the data used for the development), compared with `r f2(rmse[["full"]])` for the full model and `r f2(rmse[["abdomen_weight"]])` for a model with abdomen and weight only. Because of the selection, the confidence intervals in Table 1 are too narrow, and the table should not be read as a list of the determinants of body fat.

## 9. Summary

| | |
|---|---|
| **What it is** | The computer adds or removes predictors one at a time, by AIC, BIC or *p* value |
| **How (R)** | `step(lm(y ~ ., d))` backward with AIC; `k = log(n)` for BIC; `scope` and `direction` for forward; `leaps::regsubsets()` for all subsets |
| **What it costs** | *p* values too small, intervals too narrow, weak effects too large, $R^2$ too high |
| **What it found in noise** | A significant model in `r pct(mean(shuffled[, "p_model"] < .05))` of the shuffled data sets |
| **How stable it was** | `r num(n_models)` different models in 1,000 bootstrap samples |
| **Check it with** | Bootstrap inclusion frequencies, and cross-validation that repeats the selection |
| **Better** | Predictors chosen beforehand, the full model, or shrinkage ([ridge, lasso](EXAMPLE_REGULARIZED_REGRESSION.Rmd)) |
| **Not the same as** | [Hierarchical regression](EXAMPLE_HIERARCHICAL_REGRESSION.Rmd), where the analyst decides the order |
