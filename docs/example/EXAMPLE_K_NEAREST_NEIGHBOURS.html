k-Nearest Neighbours Regression: What Is This House Worth? Ask the Neighbours

  • Show All Code
  • Hide All Code
  • View Source
k-nearest neighbours regression in R, by hand and with FNN, on 21,600 house sales around Seattle: distances, scaling and weighting the predictors, choosing k by validation on later sales, the bias-variance trade-off, comparable houses for one sale, the curse of dimensionality with noise predictors, kNN against regression, GAM and random forest, a local correction of a regression, prediction intervals by conformal prediction, and APA reporting.

The question: what an estate agent does

How do you find out what a house is worth? You look at what similar houses nearby were sold for, and take something like the average. Estate agents call these houses comparables. No formula, no coefficients.

k-nearest neighbours (kNN) is this, done by a computer. To predict a case, find the \(k\) most similar cases in the data and average their outcomes. It is the simplest method of machine learning, more than 70 years old (Fix and Hodges described it in 1951; Cover & Hart, 1967, worked out how good it can be), and it has no training at all. The whole model is the data.

All the difficulty is in two words: how many (k), and what is similar. Is a house of the same size at a distance of 3 km more similar than a house twice as large next door?

3. The method step by step, with formulas

Step 1: a distance

The usual one is Euclidean. With the predictors \(x_1, \dots, x_p\),

\[d(x, x') = \sqrt{\sum_{j=1}^{p} w_j^2\, (x_j - x'_j)^2}\]

The weights \(w_j\) are part of the method, whether one chooses them or not. If a predictor is measured in other units, its weight changes.

Step 2: the neighbours, and their mean

Let \(N_k(x)\) be the \(k\) training cases with the smallest distance to \(x\). The prediction is

\[\hat f(x) = \frac{1}{k}\sum_{i \in N_k(x)} y_i\]

By hand, for the first house of the validation set, with place and size only:

Code 
new <- valid[1, ]

  (train$east - new$east)^2 + (train$north - new$north)^2 + (2 * (train$lsize - new$lsize))^2
) # a doubling of the size counts as 2 km

Step 3: the choice of \(k\)

With \(k = 1\) the prediction jumps from house to house and copies every accident of a single sale: no bias, much variance. With \(k = n\) it is the mean of all houses: no variance, much bias. In between is the best value, and it must be found by trying.

Step 4: no training, slow prediction

There is nothing to estimate. But for each new case all the distances must be computed. Programs use search trees (FNN does) that avoid most of the work in few dimensions.

Weights for the predictors

But why the same weight? Place matters more than the size of the garden. We can search for better weights on the validation set, one predictor at a time, doubling or halving its weight as long as it helps:

Code 
w <- setNames(rep(1, length(vars)), vars)
score <- function(w, k = 8) rmse(knn(Z(train, w), Z(valid, w), k), valid$logp)
current <- score(w); history <- data.frame(step = 0, changed = "start", rmse = current)
for (round in 1:4) {
  for (v in vars) {
    for (f in c(2, 0.5)) {
      repeat {
        trial <- w
        trial[v] <- trial[v] * f
        s <- score(trial)
        if (s < current - 1e-5) {
          w <- trial
          current <- s
          history <- rbind(history, data.frame(step = nrow(history), changed = v, rmse = s))
        } else {
          break
        }
      }
    }
  }
}

6. Against other methods

learn <- rbind(train, valid) # the test may use everything before April
Zl <- sweep(sweep(sweep(as.matrix(learn[, vars]), 2, centre), 2, spread, "/"), 2, w, "*")
knn_pred <- knn.reg(Zl, Zn, learn$logp, k = k_w)$pred

linz <- lm(logp ~ zip + lsize + grade + built + llot + view + water, data = learn)

  logp ~ s(east, north, k = 150) +
    s(lsize, k = 6) +
    s(grade, k = 6) +
    s(built, k = 8) +
    s(llot, k = 6) +

    water,

set.seed(161)
rf <- ranger(
  logp ~ east + north + lsize + grade + built + llot + view + water,
  data = learn,
  num.trees = 500
)
# a regression for the house, and kNN for the place: the mean residual of the nearest houses
res_learn <- resid(lin)
local <- knn.reg(learn[, place], test[, place], res_learn, k = 15)$pred
preds <- list(
  `Linear regression` = predict(lin, test),
  `Regression + postal codes` = predict(linz, test),

    Z(test),
    learn$logp,

  • Plain linear regression misses half of the houses by more than 17%; the weighted kNN by more than 11%. Knowing the neighbours is worth a lot.
  • A regression with postal codes comes close to kNN (RMSE 0.089 against 0.086). It uses a simple formula for what is simple (size, grade, age), and the neighbourhood for the rest.
  • The same idea without postal codes: a regression for the house and kNN for the place, that is, the linear regression plus the average residual of the 15 nearest houses. A few lines of code take the RMSE of the regression from 0.120 to 0.092. It does not reach the weighted kNN, because the formula of the regression is too simple for the rest, too.
  • The GAM with a smooth map and smooth curves has the smallest error, 0.081, and the random forest has 0.086.

Where kNN loses, it is because it cannot learn that a doubling of the size adds a certain share of the price everywhere. It must find, for every place and grade, houses of the right size. The GAM adds up one map and one curve per predictor, and learns each of them from all the sales.

7. The curse of dimensionality

In many dimensions nothing is near. Add predictors that mean nothing (random numbers), and watch:

Code 
set.seed(162)
extra <- c(0, 1, 2, 4, 8, 16)
noise <- matrix(
  rnorm((nrow(learn) + nrow(test)) * max(extra)),
  ncol = max(extra),
  dimnames = list(NULL, paste0("noise", seq_len(max(extra))))
)
in_learn <- seq_len(nrow(learn)); in_test <- nrow(learn) + seq_len(nrow(test))
curse <- sapply(extra, function(m) {
  A <- cbind(Z(learn), noise[in_learn, seq_len(m), drop = FALSE])
  B <- cbind(Z(test), noise[in_test, seq_len(m), drop = FALSE])
  rmse(knn.reg(A, B, learn$logp, k = 8)$pred, test$logp)
})
lm_noise <- sapply(extra, function(m) {
  L <- cbind(learn[, c("logp", vars)], noise[in_learn, seq_len(m), drop = FALSE])
  Te <- cbind(test[, vars], noise[in_test, seq_len(m), drop = FALSE])
  rmse(predict(lm(logp ~ ., data = L), Te), test$logp)
})
rbind(noise_predictors = extra, kNN = round(curse, 4), linear_regression = round(lm_noise, 4))

  set.seed(163)

With 16 useless predictors the error of kNN goes from 0.090 to 0.129. Linear regression hardly notices (0.120 and 0.120): it gives them coefficients near zero. kNN cannot ignore a predictor; each one has its weight in the distance. The second output shows the geometry: among 2,000 random points, the nearest is at 2% of the distance of the farthest in 2 dimensions, and at 35% in 24. “Nearest” loses its meaning (Beyer et al., 1999).

8. How sure is the prediction? Conformal intervals

kNN has no standard errors. Conformal prediction gives intervals for any method, with one simple idea: look at the errors on sales that were not used, and take their 90% quantile (Lei et al., 2018). Here: predict the validation sales from the training sales, and use those errors for the test.

Code 
err   <- abs(knn(Z(train, w), Z(valid, w), k_w) - valid$logp)
q90   <- sort(err)[ceiling(0.9 * (length(err) + 1))]
inside <- abs(knn_pred - test$logp) <= q90
c(half_width_log10 = q90, factor = 10^q90, coverage_in_test = mean(inside))
half_width_log10           factor coverage_in_test 
       0.1338998        1.3611305        0.8953771
Code 
cheap <- cut(
  knn_pred,
  quantile(knn_pred, 0:4 / 4),
  include.lowest = TRUE,
  labels = c("cheapest quarter", "2", "3", "most expensive quarter")
)
round(tapply(inside, cheap, mean), 3)
      cheapest quarter                      2                      3 most expensive quarter 
                 0.863                  0.910                  0.928                  0.882

The 90% interval goes from the prediction divided by 1.36 to the prediction times 1.36. In the test 89.5% of the houses were inside. The coverage is right on average, and not in every group: it ranges from 86% to 93% across the quarters of the predicted price, because the interval has the same width everywhere.

9. Things to keep in mind

  • Scale, then weight. Both decide the result. Use the training data for the centre and the spread.
  • Choose \(k\) by validation, on cases that resemble the future. An odd \(k\) has no meaning in regression.
  • At the edges kNN is biased: the neighbours of the largest house are all smaller. The prediction can never leave the range of the data.
  • Few, strong predictors. With many weak ones use other methods, or reduce them first.
  • Categories need a distance of their own (0 if equal, 1 if not, times a weight).
  • Dependence: the same house sold twice, flats of the same building. Keep them on the same side of the split.
  • Distance in space is not distance in life. Two houses on the opposite shores of a lake are near on the map.
  • It is a smoother. kNN with one predictor is a rough cousin of LOESS, which fits a line instead of a mean and has less bias at the ends.

10. Reporting the results in APA style

A report (APA 7th edition) needs the predictors and their scaling, the distance and the weights, \(k\) and how it was chosen, the split, the errors in understandable units, and simpler alternatives. The numbers come from the R objects:

Code 
r <- results[order(results$rmse), ]
apa_table <- data.frame(
  Model = as.character(r$model),
  rmse = f3(r$rmse),
  med = pct(r$median_error, 1)
)

Method (data analysis):

We predicted the log price of 2,877 houses sold in King County, Washington, in April and May 2015 from 18,736 earlier sales (May 2014–March 2015) with k-nearest neighbours regression. Predictors were the position (km), log living space, grade, year of construction, log lot size, view and waterfront, standardised with the training data. The number of neighbours and the weights of the predictors in the Euclidean distance were chosen with the sales of February and March 2015. Linear regression with and without postal codes, a generalized additive model with a smooth of the position, a random forest, and a regression corrected by the residuals of neighbouring houses served for comparison. Prediction intervals are split-conformal (Lei et al., 2018). Analyses were conducted in R (Version 4.6.2; R Core Team, 2026) with the package FNN.

Results:

With k = 8 and weighted predictors, half of the predictions were within 11.2% of the price (RMSE of log10 price = 0.086), compared with 16.8% for linear regression (Table 1). A linear regression corrected by the mean residual of the 15 nearest houses had a median error of 12.5%. The 90% conformal intervals (predicted price divided or multiplied by 1.36) contained 89.5% of the prices.

## The question: what an estate agent does

How do you find out what a house is worth? You look at what **similar houses nearby** were sold for, and take something like the average. Estate agents call these houses *comparables*. No formula, no coefficients.

**k-nearest neighbours** (kNN) is this, done by a computer. To predict a case, find the $k$ most similar cases in the data and average their outcomes. It is the simplest method of machine learning, more than 70 years old (Fix and Hodges described it in 1951; Cover & Hart, 1967, worked out how good it can be), and it has no training at all. The whole model is the data.

All the difficulty is in two words: how many (**k**), and what is **similar**. Is a house of the same size at a distance of 3 km more similar than a house twice as large next door?

## 3. The method step by step, with formulas

### Step 1: a distance

The usual one is Euclidean. With the predictors $x_1, \dots, x_p$,

$$d(x, x') = \sqrt{\sum_{j=1}^{p} w_j^2\, (x_j - x'_j)^2}$$

The **weights** $w_j$ are part of the method, whether one chooses them or not. If a predictor is measured in other units, its weight changes.

### Step 2: the neighbours, and their mean

Let $N_k(x)$ be the $k$ training cases with the smallest distance to $x$. The prediction is

$$\hat f(x) = \frac{1}{k}\sum_{i \in N_k(x)} y_i$$

By hand, for the first house of the validation set, with place and size only:

```{r by_hand}
new <- valid[1, ]
d <- sqrt(
  (train$east - new$east)^2 + (train$north - new$north)^2 + (2 * (train$lsize - new$lsize))^2
) # a doubling of the size counts as 2 km
near <- order(d)[1:5]
cbind(
  distance = round(d[near], 2),
  km = round(sqrt((train$east[near] - new$east)^2 + (train$north[near] - new$north)^2), 2),
  train[near, c("price", "built", "grade")],
  size = round(2^train$lsize[near])
)
c(predicted = 10^mean(train$logp[near]), sold_for = new$price)
```

### Step 3: the choice of $k$

With $k = 1$ the prediction jumps from house to house and copies every accident of a single sale: no bias, much variance. With $k = n$ it is the mean of all houses: no variance, much bias. In between is the best value, and it must be found by trying.

### Step 4: no training, slow prediction

There is nothing to estimate. But for each new case all the distances must be computed. Programs use search trees (`FNN` does) that avoid most of the work in few dimensions.

## 4. What is similar? Scaling

Try three definitions, each with several $k$, on the validation sales:

```{r scaling}
vars <- c("east", "north", "lsize", "grade", "built", "llot", "view", "water")
centre <- colMeans(train[, vars]); spread <- apply(train[, vars], 2, sd)
Z <- function(d, w = rep(1, length(vars))) {
  sweep(sweep(sweep(as.matrix(d[, vars]), 2, centre), 2, spread, "/"), 2, w, "*")
} # standardise with the training data, then weight
knn <- function(Ztr, Zte, k, y = train$logp) knn.reg(Ztr, Zte, y, k = k)$pred
ks <- c(1, 2, 3, 5, 8, 12, 20, 35, 60, 100)
place <- c("east", "north")
curves <- rbind(
  data.frame(
    k = ks,
    rmse = sapply(ks, function(k) rmse(knn(train[, place], valid[, place], k), valid$logp)),
    what = "place only"
  ),
  data.frame(
    k = ks,
    rmse = sapply(ks, function(k) rmse(knn(train[, vars], valid[, vars], k), valid$logp)),

  ),
  data.frame(
    k = ks,

    what = "all predictors, standardised"
  )
)
best <- do.call(rbind, lapply(split(curves, curves$what), function(d) d[which.min(d$rmse), ]))
best
```

- The classic **U-shape**: too few neighbours are noisy, too many are not similar.
- With **place only**, `r f3(best["place only", "rmse"])` at best.
- With all the predictors in **raw units**, `r f3(best["all predictors, raw units", "rmse"])`. The year of construction runs over a hundred units and the waterfront over one, so the years decide who is a neighbour.
- **Standardised**, `r f3(best["all predictors, standardised", "rmse"])`. Each predictor has the same weight now.

### Weights for the predictors

But why the **same** weight? Place matters more than the size of the garden. We can search for better weights on the validation set, one predictor at a time, doubling or halving its weight as long as it helps:

```{r weights}
w <- setNames(rep(1, length(vars)), vars)
score <- function(w, k = 8) rmse(knn(Z(train, w), Z(valid, w), k), valid$logp)
current <- score(w); history <- data.frame(step = 0, changed = "start", rmse = current)
for (round in 1:4) {
  for (v in vars) {
    for (f in c(2, 0.5)) {
      repeat {
        trial <- w
        trial[v] <- trial[v] * f
        s <- score(trial)
        if (s < current - 1e-5) {
          w <- trial
          current <- s
          history <- rbind(history, data.frame(step = nrow(history), changed = v, rmse = s))
        } else {
          break
        }
      }
    }
  }
}
w
k_w <- ks[which.min(sapply(ks, function(k) score(w, k)))]
c(standardised = best["all predictors, standardised", "rmse"], weighted = score(w, k_w), k = k_w)
```

The search gives the most weight to `r paste(names(sort(w, decreasing = TRUE))[1:3], collapse = ", ")`, and the error falls to `r f3(score(w, k_w))`. **The weights are the model.** They were tuned on the validation sales, so that error is too good; the test set will tell. (Weighting the neighbours themselves by their distance is another refinement, which helps a little.)

## 6. Against other methods

```{r compare}
learn <- rbind(train, valid) # the test may use everything before April
Zl <- sweep(sweep(sweep(as.matrix(learn[, vars]), 2, centre), 2, spread, "/"), 2, w, "*")
knn_pred <- knn.reg(Zl, Zn, learn$logp, k = k_w)$pred
lin  <- lm(logp ~ east + north + lsize + grade + built + llot + view + water, data = learn)
# each postal code its own level
linz <- lm(logp ~ zip + lsize + grade + built + llot + view + water, data = learn)
gm <- bam(
  logp ~ s(east, north, k = 150) +
    s(lsize, k = 6) +
    s(grade, k = 6) +
    s(built, k = 8) +
    s(llot, k = 6) +
    view +
    water,
  data = learn
)
set.seed(161)
rf <- ranger(
  logp ~ east + north + lsize + grade + built + llot + view + water,
  data = learn,
  num.trees = 500
)
# a regression for the house, and kNN for the place: the mean residual of the nearest houses
res_learn <- resid(lin)
local <- knn.reg(learn[, place], test[, place], res_learn, k = 15)$pred
preds <- list(
  `Linear regression` = predict(lin, test),
  `Regression + postal codes` = predict(linz, test),
  `kNN, standardised` = knn.reg(
    Z(learn),
    Z(test),
    learn$logp,
    k = best["all predictors, standardised", "k"]
  )$pred,
  `kNN, weighted` = knn_pred,
  `GAM with a map` = as.numeric(predict(gm, test)),
  `Random forest` = predict(rf, test)$predictions,
  `Regression + kNN of its residuals` = predict(lin, test) + local
)
results <- data.frame(
  model = names(preds),
  rmse = sapply(preds, rmse, b = test$logp),
  median_error = sapply(preds, function(p) median(abs(10^(p - test$logp) - 1))),
  row.names = NULL
)
results <- results[order(results$rmse), ]
print(
  transform(results, rmse = round(rmse, 4), median_error = round(median_error, 3)),
  row.names = FALSE
)
get <- function(m, col = "rmse") results[results$model == m, col]
```

```{r compare_chart}
ggplot(results, aes(median_error, model)) +
```

- Plain **linear regression** misses half of the houses by more than `r pct(get("Linear regression", "median_error"))`; the weighted **kNN** by more than `r pct(get("kNN, weighted", "median_error"))`. Knowing the neighbours is worth a lot.
- A regression with **postal codes** comes close to kNN (RMSE `r f3(get("Regression + postal codes"))` against `r f3(get("kNN, weighted"))`). It uses a simple formula for what is simple (size, grade, age), and the neighbourhood for the rest.
- The same idea without postal codes: a **regression for the house and kNN for the place**, that is, the linear regression plus the average residual of the 15 nearest houses. A few lines of code take the RMSE of the regression from `r f3(get("Linear regression"))` to `r f3(get("Regression + kNN of its residuals"))`. It does not reach the weighted kNN, because the formula of the regression is too simple for the rest, too.
- The **GAM** with a smooth map and smooth curves has the smallest error, `r f3(get("GAM with a map"))`, and the **random forest** has `r f3(get("Random forest"))`.

Where kNN loses, it is because it cannot learn that a doubling of the size adds a certain share of the price **everywhere**. It must find, for every place and grade, houses of the right size. The GAM adds up one map and one curve per predictor, and learns each of them from all the sales.

## 7. The curse of dimensionality

In many dimensions nothing is near. Add predictors that mean nothing (random numbers), and watch:

```{r curse}
set.seed(162)
extra <- c(0, 1, 2, 4, 8, 16)
noise <- matrix(
  rnorm((nrow(learn) + nrow(test)) * max(extra)),
  ncol = max(extra),
  dimnames = list(NULL, paste0("noise", seq_len(max(extra))))
)
in_learn <- seq_len(nrow(learn)); in_test <- nrow(learn) + seq_len(nrow(test))
curse <- sapply(extra, function(m) {
  A <- cbind(Z(learn), noise[in_learn, seq_len(m), drop = FALSE])
  B <- cbind(Z(test), noise[in_test, seq_len(m), drop = FALSE])
  rmse(knn.reg(A, B, learn$logp, k = 8)$pred, test$logp)
})
lm_noise <- sapply(extra, function(m) {
  L <- cbind(learn[, c("logp", vars)], noise[in_learn, seq_len(m), drop = FALSE])
  Te <- cbind(test[, vars], noise[in_test, seq_len(m), drop = FALSE])
  rmse(predict(lm(logp ~ ., data = L), Te), test$logp)
})
rbind(noise_predictors = extra, kNN = round(curse, 4), linear_regression = round(lm_noise, 4))
dist_ratio <- sapply(c(2, 8, 24), function(p) {
  set.seed(163)
  u <- matrix(runif(2000 * p), ncol = p)
  d <- sqrt(colSums((t(u[-1, ]) - u[1, ])^2))
  min(d) / max(d)
})
setNames(round(dist_ratio, 2), paste(c(2, 8, 24), "dimensions"))
```

With 16 useless predictors the error of kNN goes from `r f3(curse[1])` to `r f3(curse[6])`. Linear regression hardly notices (`r f3(lm_noise[1])` and `r f3(lm_noise[6])`): it gives them coefficients near zero. kNN cannot ignore a predictor; each one has its weight in the distance. The second output shows the geometry: among 2,000 random points, the nearest is at `r pct(dist_ratio[1])` of the distance of the farthest in 2 dimensions, and at `r pct(dist_ratio[3])` in 24. "Nearest" loses its meaning (Beyer et al., 1999).

## 8. How sure is the prediction? Conformal intervals

kNN has no standard errors. **Conformal prediction** gives intervals for any method, with one simple idea: look at the errors on sales that were not used, and take their 90% quantile (Lei et al., 2018). Here: predict the validation sales from the training sales, and use those errors for the test.

```{r conformal}
err   <- abs(knn(Z(train, w), Z(valid, w), k_w) - valid$logp)
q90   <- sort(err)[ceiling(0.9 * (length(err) + 1))]
inside <- abs(knn_pred - test$logp) <= q90
c(half_width_log10 = q90, factor = 10^q90, coverage_in_test = mean(inside))
cheap <- cut(
  knn_pred,
  quantile(knn_pred, 0:4 / 4),
  include.lowest = TRUE,
  labels = c("cheapest quarter", "2", "3", "most expensive quarter")
)
round(tapply(inside, cheap, mean), 3)
```

The 90% interval goes from the prediction divided by `r f2(10^q90)` to the prediction times `r f2(10^q90)`. In the test `r pct(mean(inside), 1)` of the houses were inside. The coverage is right **on average**, and not in every group: it ranges from `r pct(min(tapply(inside, cheap, mean)))` to `r pct(max(tapply(inside, cheap, mean)))` across the quarters of the predicted price, because the interval has the same width everywhere.

## 9. Things to keep in mind

- **Scale, then weight.** Both decide the result. Use the training data for the centre and the spread.
- **Choose $k$ by validation**, on cases that resemble the future. An odd $k$ has no meaning in regression.
- **At the edges** kNN is biased: the neighbours of the largest house are all smaller. The prediction can never leave the range of the data.
- **Few, strong predictors.** With many weak ones use other methods, or reduce them first.
- **Categories** need a distance of their own (0 if equal, 1 if not, times a weight).
- **Dependence**: the same house sold twice, flats of the same building. Keep them on the same side of the split.
- **Distance in space is not distance in life.** Two houses on the opposite shores of a lake are near on the map.
- **It is a smoother.** kNN with one predictor is a rough cousin of [LOESS](EXAMPLE_LOESS.Rmd), which fits a line instead of a mean and has less bias at the ends.
