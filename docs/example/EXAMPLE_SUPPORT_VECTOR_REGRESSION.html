Support Vector Regression: How Loud Is This Wing?

  • Show All Code
  • Hide All Code
  • View Source
Support vector regression in R with e1071, on NASA’s wind tunnel measurements of airfoil noise: the epsilon-insensitive loss, cost, the kernel trick and support vectors by hand, tuning cost, gamma and epsilon by cross-validation, why splitting rows at random is a mistake when they come from the same experiment, a comparison with linear regression, a GAM and a random forest, partial dependence, scaling, outliers and APA reporting.

The question: noise from the edge of a wing

When air flows over the blade of a fan, a wind turbine or a wing, it makes noise, even if nothing vibrates. In the 1980s NASA measured it in a wind tunnel: blades of different sizes, at different speeds and angles, and the sound level at many frequencies (Brooks et al., 1989). Can we predict the noise of a blade that was not measured?

The relation is smooth, and complicated: the noise has a peak at some frequency, and the peak moves with the size, the speed and the angle. A linear regression cannot follow it. Support vector regression (SVR; Cortes & Vapnik, 1995; Smola & Schölkopf, 2004) is one of the classic machine-learning methods for such problems. It has two ideas:

  1. Errors below some size do not count. Only the points that lie outside a tube around the curve have a say.
  2. Curves from distances. The prediction for a new case is a weighted sum of its similarities to some of the old ones.

This page also shows something that has nothing to do with SVR and decides whether any of the results are true: how the test data are separated from the training data.

Split by experiment, not by row

If we put single rows at random into the training and the test set, then for nearly every test row its neighbours in the same spectrum are in the training set. A method that only connects the dots would look brilliant. But the question is about blades that were not measured. So whole experiments go to one side or the other:

3. The method step by step, with formulas

Step 1: a tube instead of a line

Least squares punishes every error, by its square. SVR does not punish errors smaller than \(\varepsilon\) at all, and larger ones only in proportion:

\[L_\varepsilon(e) = \max(0,\; |e| - \varepsilon)\]

Code 
e <- seq(-3, 3, by = 0.01)
losses <- rbind(
  data.frame(e, loss = e^2, kind = "squared (least squares)"),
  data.frame(e, loss = abs(e), kind = "absolute (median regression)"),
  data.frame(e, loss = pmax(0, abs(e) - 1), kind = "ε-insensitive, ε = 1 (SVR)")
)
ggplot(losses, aes(e, loss, colour = kind)) +
  geom_line(linewidth = 1) +
  coord_cartesian(ylim = c(0, 4)) +
  scale_colour_manual(values = c("#1baf7a", "#eb6834", "#2a78d6"), name = NULL) +
  labs(title = "Three ways to count an error", x = "error", y = "loss") +
  theme_bw() +
  theme(legend.position = "bottom")

Step 2: as flat as possible

For a linear function \(f(x) = w^\top x + b\), SVR minimises

\[\frac{1}{2}\lVert w \rVert^2 + C \sum_i L_\varepsilon\big(y_i - f(x_i)\big)\]

The first part asks for a flat function (a penalty like that of ridge regression), the second for small errors outside the tube. The cost \(C\) is the exchange rate: a large \(C\) follows the data, a small \(C\) stays flat.

Step 3: support vectors

The solution can be written with one weight per training case:

\[f(x) = \sum_i \alpha_i\, (x_i^\top x) + b, \qquad -C \le \alpha_i \le C\]

Cases strictly inside the tube have \(\alpha_i = 0\): they could be deleted without changing anything. The others are the support vectors. In the formula the predictors appear only in products \(x_i^\top x\) of two cases.

Step 4: the kernel

So replace the product by any other measure of similarity, a kernel \(K(x_i, x)\). The most used is the radial one,

\[K(x_i, x) = \exp\!\left(-\gamma\, \lVert x_i - x \rVert^2\right)\]

which is 1 for identical cases and falls to 0 with the distance. Now \(f\) is a sum of bumps centred at the support vectors, and can take any smooth shape, without ever naming a formula. \(\gamma\) decides how wide the bumps are: a small \(\gamma\) gives a stiff function, a large one a wiggly function.

Step 5: check the formula by hand

Code 
small <- svm(
  db ~ lf + angle + chord + speed + lt,
  data = train,
  cost = 10,
  gamma = 0.2,
  epsilon = 0.1
) # predictors and outcome are standardised inside
vars  <- c("lf", "angle", "chord", "speed", "lt")
Zt <- scale(
  as.matrix(test[, vars]),
  center = small$x.scale$`scaled:center`,
  scale = small$x.scale$`scaled:scale`
)
SV <- small$SV # the support vectors, standardised
# exp(-gamma * squared distance)
K <- exp(-0.2 * outer(rowSums(Zt^2), rowSums(SV^2), "+") + 2 * 0.2 * Zt %*% t(SV))
f_std <- drop(K %*% small$coefs) - small$rho
by_hand <- f_std * small$y.scale$`scaled:scale` + small$y.scale$`scaled:center`
max(abs(by_hand - predict(small, test)))

4. Tuning: cost, gamma, epsilon

The three settings are chosen by cross-validation in the training set, again by experiment:

Code 
set.seed(153)
train_runs <- unique(train$run)
fold_of <- setNames(sample(rep(1:5, length.out = length(train_runs))), train_runs)
fold <- fold_of[train$run]
form <- db ~ lf + angle + chord + speed + lt
cv_error <- function(cost, gamma, epsilon, folds = fold) {
  err <- unlist(lapply(1:5, function(k) {
    m <- svm(form, data = train[folds != k, ], cost = cost, gamma = gamma, epsilon = epsilon)
    predict(m, train[folds == k, ]) - train$db[folds == k]
  }))
  sqrt(mean(err^2))
}
grid <- expand.grid(cost = c(0.5, 2, 10, 50, 200), gamma = c(0.02, 0.05, 0.1, 0.2, 0.5, 1))
grid$rmse <- mapply(cv_error, grid$cost, grid$gamma, 0.1)
best <- grid[which.min(grid$rmse), ]
eps  <- c(0.01, 0.05, 0.1, 0.2, 0.4)
eps_rmse <- sapply(eps, function(e) cv_error(best$cost, best$gamma, e))
best_eps <- eps[which.min(eps_rmse)]
best; rbind(epsilon = eps, rmse = eps_rmse)

6. What has the model learned?

SVR has no coefficients to read. Partial dependence shows the average prediction as one predictor changes:

Code 
pd <- function(v, values) {
  sapply(values, function(x) {
    z <- train
    z[[v]] <- x
    mean(predict(svr, z))
  })
}
pd_data <- do.call(
  rbind,
  lapply(
    list(
      c("lf", "log10 frequency"),
      c("angle", "angle (degrees)"),
      c("chord", "chord (m)"),
      c("speed", "speed (m/s)")
    ),
    function(p) {
      values <- seq(min(train[[p[1]]]), max(train[[p[1]]]), length.out = 25)
      data.frame(x = values, db = pd(p[1], values), what = p[2])
    }
  )
)
pd_data$what <- factor(pd_data$what, levels = unique(pd_data$what))
ggplot(pd_data, aes(x, db)) +
  geom_line(colour = "#2a78d6", linewidth = 1) +
  facet_wrap(~what, scales = "free_x") +
  labs(title = "Partial dependence of the sound level", x = NULL, y = "predicted dB") +
  theme_bw()
Code 
range_of <- tapply(pd_data$db, pd_data$what, function(v) diff(range(v)))
round(range_of, 1)
log10 frequency angle (degrees)       chord (m)     speed (m/s)

The frequency changes the prediction most (by 20.3 dB over its range), then the length of the blade (8.2 dB) and the angle (7.0), and the speed least (3.0). The peak that moves with the conditions is an interaction, which such averages hide.

Code 
sv_share <- sapply(c(0.01, 0.1, 0.4, 0.8), function(e) {
  svm(form, data = train, cost = best$cost, gamma = best$gamma, epsilon = e)$tot.nSV / nrow(train)
})
setNames(round(sv_share, 2), paste("epsilon", c(0.01, 0.1, 0.4, 0.8)))
epsilon 0.01  epsilon 0.1  epsilon 0.4  epsilon 0.8 
        0.97         0.66         0.18         0.06
  • Scale the predictors. The kernel adds squared distances. Without scaling, degrees of angle count thousands of times more than metres of chord, and the error rises to 5.7 dB. svm() scales by default; the same centre and scale must be used for new data, as predict() does.
  • Outliers count in proportion and not by their square. Twenty wrong values moved the error of the SVR to 2.54 and that of the GAM to 4.11 dB.
  • \(\varepsilon\) decides how many support vectors there are: 97% of the rows with 0.01, 18% with 0.4. Fewer support vectors make a smaller and faster model.

8. Things to keep in mind

  • Keep together what belongs together: experiments, patients, schools, days. In the split and in the tuning.
  • Tune on a grid of factors (1, 10, 100, …), then refine. The three settings interact.
  • No intervals, no tests. SVR gives a number. For uncertainty use bootstrap, conformal prediction, or a Gaussian process, its probabilistic relative.
  • No extrapolation. Far from all support vectors the radial kernel gives 0 and the prediction returns to the constant \(b\).
  • Slow for large data: the time grows with the square to the cube of the rows. Above some ten thousand rows take boosting, forests or neural networks.
  • Categorical predictors must be coded as dummies, and they are then measured by the same distance as the rest.
  • Other kernels: linear (many predictors, few rows), polynomial. The radial one is the usual start.
  • A simple model is often close. Always fit one.

9. Reporting the results in APA style

A report (APA 7th edition) needs the unit of splitting, the preprocessing, the kernel, the tuning grid and its validation, the chosen settings, and the test error with its uncertainty and with simpler models. The numbers come from the R objects:

Code 
o <- order(results$test_rmse)
apa_table <- data.frame(
  Model = as.character(results$model)[o],
  rmse = f2(results$test_rmse[o]),
  ci = paste0("[", f2(results$low[o]), ", ", f2(results$high[o]), "]"),
  r2 = f2(results$R2[o])
)

Method (data analysis):

We predicted the sound level of airfoils (1,503 measurements from 106 wind tunnel experiments; Brooks et al., 1989) from log frequency, angle of attack, chord length, air speed and the log thickness of the boundary layer with support vector regression with a radial kernel (Smola & Schölkopf, 2004). Predictors and outcome were standardised with the training data. A random quarter of the experiments was the test set. Cost, γ and ε were chosen by five-fold cross-validation in the training set, with whole experiments in one fold. Linear and quadratic regression, a generalized additive model and a random forest served for comparison. Confidence intervals of the test error are from 1,000 bootstrap samples of experiments. Analyses were conducted in R (Version 4.6.2; R Core Team, 2026) with the package e1071.

Results:

The selected settings were C = 10, γ = 0.1 and ε = 0.1 (cross-validated RMSE = 2.86 dB), with 742 support vectors. On 26 experiments that were not used for training, the RMSE was 2.60 dB, 95% CI [2.30, 2.87], compared with 5.16 for linear regression (Table 1). Cross-validation with single measurements left out at random would have suggested an RMSE of 1.43 dB, and the model chosen in this way had 3.51 dB on new experiments.

Points to remember:

  • Say what was kept together in the split.
  • Report the kernel, the grid and the chosen settings.

## The question: noise from the edge of a wing

When air flows over the blade of a fan, a wind turbine or a wing, it makes noise, even if nothing vibrates. In the 1980s NASA measured it in a wind tunnel: blades of different sizes, at different speeds and angles, and the sound level at many frequencies (Brooks et al., 1989). Can we predict the noise of a blade that was not measured?

The relation is smooth, and complicated: the noise has a peak at some frequency, and the peak moves with the size, the speed and the angle. A linear regression cannot follow it. **Support vector regression** (SVR; Cortes & Vapnik, 1995; Smola & Schölkopf, 2004) is one of the classic machine-learning methods for such problems. It has two ideas:

1. **Errors below some size do not count.** Only the points that lie outside a tube around the curve have a say.
2. **Curves from distances.** The prediction for a new case is a weighted sum of its similarities to some of the old ones.

This page also shows something that has nothing to do with SVR and decides whether any of the results are true: **how the test data are separated from the training data**.

## 3. The method step by step, with formulas

### Step 1: a tube instead of a line

Least squares punishes every error, by its square. SVR does not punish errors smaller than $\varepsilon$ at all, and larger ones only in proportion:

$$L_\varepsilon(e) = \max(0,\; |e| - \varepsilon)$$

```{r loss_chart}
e <- seq(-3, 3, by = 0.01)
losses <- rbind(
  data.frame(e, loss = e^2, kind = "squared (least squares)"),
  data.frame(e, loss = abs(e), kind = "absolute (median regression)"),
  data.frame(e, loss = pmax(0, abs(e) - 1), kind = "ε-insensitive, ε = 1 (SVR)")
)
ggplot(losses, aes(e, loss, colour = kind)) +
  geom_line(linewidth = 1) +
  coord_cartesian(ylim = c(0, 4)) +
  scale_colour_manual(values = c("#1baf7a", "#eb6834", "#2a78d6"), name = NULL) +
  labs(title = "Three ways to count an error", x = "error", y = "loss") +
  theme_bw() +
  theme(legend.position = "bottom")
```

### Step 2: as flat as possible

For a linear function $f(x) = w^\top x + b$, SVR minimises

$$\frac{1}{2}\lVert w \rVert^2 + C \sum_i L_\varepsilon\big(y_i - f(x_i)\big)$$

The first part asks for a **flat** function (a penalty like that of [ridge regression](EXAMPLE_REGULARIZED_REGRESSION.Rmd)), the second for small errors outside the tube. The **cost** $C$ is the exchange rate: a large $C$ follows the data, a small $C$ stays flat.

### Step 3: support vectors

The solution can be written with one weight per training case:

$$f(x) = \sum_i \alpha_i\, (x_i^\top x) + b, \qquad -C \le \alpha_i \le C$$

Cases strictly **inside** the tube have $\alpha_i = 0$: they could be deleted without changing anything. The others are the **support vectors**. In the formula the predictors appear only in products $x_i^\top x$ of two cases.

### Step 4: the kernel

So replace the product by any other measure of similarity, a **kernel** $K(x_i, x)$. The most used is the radial one,

$$K(x_i, x) = \exp\!\left(-\gamma\, \lVert x_i - x \rVert^2\right)$$

which is 1 for identical cases and falls to 0 with the distance. Now $f$ is a sum of bumps centred at the support vectors, and can take any smooth shape, without ever naming a formula. $\gamma$ decides how **wide** the bumps are: a small $\gamma$ gives a stiff function, a large one a wiggly function.

### Step 5: check the formula by hand

```{r by_hand}
small <- svm(
  db ~ lf + angle + chord + speed + lt,
  data = train,
  cost = 10,
  gamma = 0.2,
  epsilon = 0.1
) # predictors and outcome are standardised inside
vars  <- c("lf", "angle", "chord", "speed", "lt")
Zt <- scale(
  as.matrix(test[, vars]),
  center = small$x.scale$`scaled:center`,
  scale = small$x.scale$`scaled:scale`
)
SV <- small$SV # the support vectors, standardised
# exp(-gamma * squared distance)
K <- exp(-0.2 * outer(rowSums(Zt^2), rowSums(SV^2), "+") + 2 * 0.2 * Zt %*% t(SV))
f_std <- drop(K %*% small$coefs) - small$rho
by_hand <- f_std * small$y.scale$`scaled:scale` + small$y.scale$`scaled:center`
max(abs(by_hand - predict(small, test)))
c(support_vectors = small$tot.nSV, training_rows = nrow(train))
```

The prediction is what step 4 says. `r small$tot.nSV` of the `r num(nrow(train))` training rows are support vectors.

## 4. Tuning: cost, gamma, epsilon

The three settings are chosen by cross-validation in the training set, again **by experiment**:

```{r tuning}
set.seed(153)
train_runs <- unique(train$run)
fold_of <- setNames(sample(rep(1:5, length.out = length(train_runs))), train_runs)
fold <- fold_of[train$run]
form <- db ~ lf + angle + chord + speed + lt
cv_error <- function(cost, gamma, epsilon, folds = fold) {
  err <- unlist(lapply(1:5, function(k) {
    m <- svm(form, data = train[folds != k, ], cost = cost, gamma = gamma, epsilon = epsilon)
    predict(m, train[folds == k, ]) - train$db[folds == k]
  }))
  sqrt(mean(err^2))
}
grid <- expand.grid(cost = c(0.5, 2, 10, 50, 200), gamma = c(0.02, 0.05, 0.1, 0.2, 0.5, 1))
grid$rmse <- mapply(cv_error, grid$cost, grid$gamma, 0.1)
best <- grid[which.min(grid$rmse), ]
eps  <- c(0.01, 0.05, 0.1, 0.2, 0.4)
eps_rmse <- sapply(eps, function(e) cv_error(best$cost, best$gamma, e))
best_eps <- eps[which.min(eps_rmse)]
best; rbind(epsilon = eps, rmse = eps_rmse)
```

```{r tuning_chart}
ggplot(grid, aes(factor(gamma), factor(cost), fill = rmse)) +
  geom_tile(colour = "white") +
  geom_text(aes(label = f2(rmse)), size = 3.4) +
  scale_fill_gradient(low = "#1baf7a", high = "white", name = "dB") +
  labs(title = "Cross-validated error, whole experiments left out", x = "γ", y = "cost C") +
  theme_minimal() +
  theme(panel.grid = element_blank())
```

The best setting is $C$ = `r best$cost`, $\gamma$ = `r best$gamma` (error `r f2(best$rmse)` dB), a fairly **stiff** function. Large $\gamma$ with a large $C$, the most flexible corner, is bad. $\varepsilon$ matters little. ($\varepsilon$ is in standard deviations of the outcome: 0.1 is `r f1(0.1 * sd(train$db))` dB.)

### The same tuning with rows at random

## 6. What has the model learned?

SVR has no coefficients to read. **Partial dependence** shows the average prediction as one predictor changes:

```{r partial}
pd <- function(v, values) {
  sapply(values, function(x) {
    z <- train
    z[[v]] <- x
    mean(predict(svr, z))
  })
}
pd_data <- do.call(
  rbind,
  lapply(
    list(
      c("lf", "log10 frequency"),
      c("angle", "angle (degrees)"),
      c("chord", "chord (m)"),
      c("speed", "speed (m/s)")
    ),
    function(p) {
      values <- seq(min(train[[p[1]]]), max(train[[p[1]]]), length.out = 25)
      data.frame(x = values, db = pd(p[1], values), what = p[2])
    }
  )
)
pd_data$what <- factor(pd_data$what, levels = unique(pd_data$what))
ggplot(pd_data, aes(x, db)) +
  geom_line(colour = "#2a78d6", linewidth = 1) +
  facet_wrap(~what, scales = "free_x") +
  labs(title = "Partial dependence of the sound level", x = NULL, y = "predicted dB") +
  theme_bw()
range_of <- tapply(pd_data$db, pd_data$what, function(v) diff(range(v)))
round(range_of, 1)
```

The frequency changes the prediction most (by `r f1(range_of[[1]])` dB over its range), then the length of the blade (`r f1(range_of[["chord (m)"]])` dB) and the angle (`r f1(range_of[["angle (degrees)"]])`), and the speed least (`r f1(range_of[["speed (m/s)"]])`). The peak that moves with the conditions is an **interaction**, which such averages hide.

## 7. Scaling, outliers, size

```{r scaling}
noscale <- svm(
  form,
  data = train,
  cost = best$cost,
  gamma = best$gamma,
  epsilon = best_eps,
  scale = FALSE
)
set.seed(157)
spoiled <- train
bad <- sample(nrow(spoiled), 20)
spoiled$db[bad] <- spoiled$db[bad] + 60 # 20 wrong measurements
out_svr <- svm(form, data = spoiled, cost = best$cost, gamma = best$gamma, epsilon = best_eps)
out_gam <- update(gam_fit, data = spoiled)
c(
  SVR = get("SVR, tuned by experiment"),
  SVR_unscaled = rmse(predict(noscale, test), test$db),
  SVR_with_outliers = rmse(predict(out_svr, test), test$db),
  GAM = get("GAM"),
  GAM_with_outliers = rmse(predict(out_gam, test), test$db)
)
sv_share <- sapply(c(0.01, 0.1, 0.4, 0.8), function(e) {
  svm(form, data = train, cost = best$cost, gamma = best$gamma, epsilon = e)$tot.nSV / nrow(train)
})
setNames(round(sv_share, 2), paste("epsilon", c(0.01, 0.1, 0.4, 0.8)))
```

- **Scale the predictors.** The kernel adds squared distances. Without scaling, degrees of angle count thousands of times more than metres of chord, and the error rises to `r f1(rmse(predict(noscale, test), test$db))` dB. `svm()` scales by default; the same centre and scale must be used for new data, as `predict()` does.
- **Outliers** count in proportion and not by their square. Twenty wrong values moved the error of the SVR to `r f2(rmse(predict(out_svr, test), test$db))` and that of the GAM to `r f2(rmse(predict(out_gam, test), test$db))` dB.
- **$\varepsilon$ decides how many support vectors there are**: `r pct(sv_share[1])` of the rows with 0.01, `r pct(sv_share[3])` with 0.4. Fewer support vectors make a smaller and faster model.

## 8. Things to keep in mind

- **Keep together what belongs together**: experiments, patients, schools, days. In the split **and** in the tuning.
- **Tune on a grid of factors** (1, 10, 100, ...), then refine. The three settings interact.
- **No intervals, no tests.** SVR gives a number. For uncertainty use bootstrap, conformal prediction, or a [Gaussian process](EXAMPLE_GAUSSIAN_PROCESS.Rmd), its probabilistic relative.
- **No extrapolation.** Far from all support vectors the radial kernel gives 0 and the prediction returns to the constant $b$.
- **Slow for large data**: the time grows with the square to the cube of the rows. Above some ten thousand rows take boosting, forests or [neural networks](EXAMPLE_NEURAL_NETWORK.Rmd).
- **Categorical predictors** must be coded as dummies, and they are then measured by the same distance as the rest.
- **Other kernels**: linear (many predictors, few rows), polynomial. The radial one is the usual start.
- **A simple model is often close**. Always fit one.
