Neural Network Regression: How Much Power Will the Plant Deliver?

  • Show All Code
  • Hide All Code
  • View Source
Neural network regression in R with nnet, on 9,568 hours of a power plant (UCI): what a neuron is, how bent lines add up to any curve, the loss with weight decay, backpropagation written by hand and checked against numerical derivatives, the same minimum as nnet, two classic mistakes, many starts and many different answers, overfitting on forty rows, choosing the size with cross-validation, why random folds flatter methods that remember, a comparison with a straight line, a GAM, nearest neighbours and a random forest on conditions that were left out, what the network has learned, and APA reporting.

The question: many bent lines

A straight line is the wrong shape for most things. Splines bend it, one predictor at a time. A neural network goes further: it adds up many little bent lines, each of which looks at all predictors at once, and it finds out by itself where to bend and which predictors to combine.

That sounds like magic and is ordinary regression: there are parameters (called weights), there is a sum of squared errors, and a computer makes the sum small. The site’s page about handwritten digits uses networks to sort things into classes. Here the network predicts a number: the electrical power of a plant from the weather.

This page writes a network by hand, derivatives included, and finds the same solution as the package. Then it asks the question that matters more than the method: what is a fair test? The answer changes the ranking of the methods.

Two details of this file will matter later. The file has been shuffled, and there is no date. And the vacuum takes only 634 different values, although it is given with two decimals.

3. The model step by step, with formulas

Step 1: standardise

Every variable gets mean 0 and SD 1 (with the mean and SD of the training data). Weights of different predictors then have comparable sizes, and the search starts in a sensible region.

Code 
standardise <- function(train, d) as.data.frame(scale(d, colMeans(train), apply(train, 2, sd)))
z <- standardise(plant, plant)
X <- as.matrix(z[, c("temperature", "vacuum", "pressure", "humidity")]); y <- z$power

Step 2: one neuron

A neuron takes a weighted sum of the predictors and sends it through an S-shaped function, the logistic function \(\sigma(u) = 1/(1 + e^{-u})\), the one from logistic regression:

\[h = \sigma(a_0 + a_1 x_1 + \dots + a_K x_K)\]

It is flat on the left, flat on the right and rises in between. The weights decide where the rise is, how steep, and in which direction.

Step 3: the network

The hidden layer has \(J\) neurons. The output is a linear regression on them:

\[\hat y = b_0 + \sum_{j=1}^{J} b_j\, \sigma\!\Big(a_{0j} + \sum_{k=1}^K a_{kj} x_k\Big)\]

That makes \(J(K + 1) + J + 1\) weights: with 4 predictors and 10 neurons, 61. Already a few S-curves add up to all kinds of shapes:

With enough neurons such a sum can come as close as you like to any continuous function (Hornik et al., 1989). That is a statement about what is possible. It does not say how many neurons or how much data you need, nor that the search will find it.

Step 4: the loss

As in least squares, with a penalty for large weights, called weight decay (\(\lambda\)). It is the penalty of ridge regression:

\[E(w) = \sum_i (y_i - \hat y_i)^2 + \lambda \sum w^2\]

Step 5: the derivatives (backpropagation)

To go downhill one needs the slope of \(E\) in the direction of every weight. The chain rule gives it, from the output backwards (Rumelhart et al., 1986). With \(r_i = -2(y_i - \hat y_i)\) and the output of neuron \(j\) for row \(i\), \(h_{ij}\):

\[\frac{\partial E}{\partial b_j} = \sum_i r_i\, h_{ij} + 2\lambda b_j, \qquad \frac{\partial E}{\partial a_{kj}} = \sum_i \underbrace{r_i\, b_j\, h_{ij}(1 - h_{ij})}_{\text{the error of neuron } j}\, x_{ik} + 2\lambda a_{kj}\]

Code 
forward <- function(w, X, J) {
  # weights in the order that nnet uses
  K <- ncol(X)
  A <- matrix(w[1:(J * (K + 1))], K + 1)
  b <- w[-(1:(J * (K + 1)))]
  h <- plogis(cbind(1, X) %*% A)
  list(h = h, b = b, yhat = drop(cbind(1, h) %*% b))
}
loss <- function(w, X, y, J, decay) sum((y - forward(w, X, J)$yhat)^2) + decay * sum(w^2)
gradient <- function(w, X, y, J, decay) {
  f <- forward(w, X, J); r <- -2 * (y - f$yhat)
  neuron_error <- (r %o% f$b[-1]) * f$h * (1 - f$h)
  c(crossprod(cbind(1, X), neuron_error), crossprod(cbind(1, f$h), r)) + 2 * decay * w
}
set.seed(202)
w0 <- runif(2 * 5 + 3, -0.7, 0.7) # 2 neurons, 13 weights, a random start
numeric_slope <- sapply(seq_along(w0), function(i) {
  d <- replace(numeric(13), i, 1e-5)
  (loss(w0 + d, X, y, 2, 0.1) - loss(w0 - d, X, y, 2, 0.1)) / 2e-5
})
max(abs(numeric_slope / gradient(w0, X, y, 2, 0.1) - 1))                    # relative difference
[1] 3.351439e-10

The formula and the numerical slopes agree. (Always do this check when you write derivatives yourself.)

5. What is a fair test?

How many neurons? The usual recipe is cross-validation with random folds. But look at the data again. 99.5% of the rows share their value of the vacuum, to two decimals, with other rows: 634 values in 9,527 hours. The most likely explanation is that the vacuum was recorded less often than the rest, and that rows with the same value come from the same period. The file does not say, and its order is destroyed. But if so, then random folds put hours of the same period in the training data and in the test. A method that remembers its neighbours would be rewarded for remembering.

So we use two kinds of folds: random rows, and whole groups of rows with the same vacuum, so that the test has conditions that the model has never seen.

Code 
set.seed(205)
group   <- as.integer(factor(plant$vacuum)); n_group <- max(group)
folds3 <- list(
  random = sample(rep(1:3, length.out = nrow(plant))),
  `new conditions` = sample(rep(1:3, length.out = n_group))[group]
)
net_predict <- function(train, test, size, decay, starts = 1, maxit = 400) {
  a <- standardise(train, train)
  b <- standardise(train, test)
  p <- sapply(starts, function(s) {
    set.seed(s)
    drop(predict(
      nnet(
        power ~ .,
        a,
        size = size,
        decay = decay,
        linout = TRUE,
        trace = FALSE,
        maxit = maxit,
        MaxNWts = 5000
      ),
      b
    ))
  })
  mean(train$power) + sd(train$power) * p
}
grid <- expand.grid(size = c(2, 5, 10, 20), decay = c(0.01, 0.1, 1))
cv <- do.call(
  cbind,
  lapply(folds3, function(f) {
    sapply(seq_len(nrow(grid)), function(i) {
      e <- numeric(nrow(plant))

        e[f == k] <- net_predict(plant[f != k, ], plant[f == k, ], grid$size[i], grid$decay[i])[,
          1
        ] -
          plant$power[f == k]
      }
      sqrt(mean(e^2))
    })
  })
)

6. The network against others

Both kinds of folds again, with new folds, for seven methods: a straight line, a GAM, the 5 nearest neighbours, a random forest, the small network that the second kind of folds chose (2 neurons, decay 0.1), the large one that random folds chose (20 neurons, decay 0.01), and the average of three such large networks.

Code 
set.seed(206)
folds5 <- list(
  `random folds` = sample(rep(1:5, length.out = nrow(plant))),
  `new conditions` = sample(rep(1:5, length.out = n_group))[group]
)
methods <- function(train, test) {
  zt <- standardise(train, train)
  zn <- standardise(train, test)
  large <- net_predict(train, test, best_r$size, best_r$decay, starts = 1:3)
  cbind(
    `straight line` = predict(lm(power ~ ., train), test),
    GAM = as.numeric(predict(
      bam(power ~ s(temperature) + s(vacuum) + s(pressure) + s(humidity), data = train),
      test
    )),
    `nearest neighbours` = FNN::knn.reg(zt[, 1:4], zn[, 1:4], train$power, k = 5)$pred,
    `random forest` = predict(
      ranger::ranger(power ~ ., train, num.trees = 300, seed = 1),
      test
    )$predictions,
    `small network` = net_predict(train, test, best_g$size, best_g$decay)[, 1],
    `large network` = large[, 1],
    `3 large networks, averaged` = rowMeans(large)
  )
}
results <- do.call(
  rbind,
  lapply(names(folds5), function(kind) {
    f <- folds5[[kind]]
    do.call(
      rbind,
      lapply(1:5, function(k) {
        p <- methods(plant[f != k, ], plant[f == k, ])
        data.frame(
          folds = kind,
          fold = k,
          method = colnames(p),
          rmse = apply(p, 2, rmse, plant$power[f == k]),
          mse = apply(p, 2, function(v) sum((v - plant$power[f == k])^2))
        )
      })
    )
  })
)

8. Things to keep in mind

  • Standardise the predictors and the outcome, with the means and SDs of the training data. In R’s nnet() add linout = TRUE for a number.
  • Try several starts, set the seed, and average the predictions.
  • Use decay (or stop early). With enough of it the exact number of neurons matters little.
  • Choose with folds that look like the use: groups, sites, times, persons.
  • Small tables: for a few thousand rows and a handful of predictors, trees (random forest, boosting), GAMs and Gaussian processes are usually as good and less work. Networks pay off with images, sound, text and very many rows.
  • Deeper networks have several hidden layers and other functions (ReLU instead of \(\sigma\)), and are trained on small batches with packages such as torch or keras3. The principles on this page are the same.
  • Outside the data S-curves become flat, so the network predicts a constant. It never says that it does not know. (Gaussian processes do, with the limits shown there.)
  • No intervals and no tests come with it. Use the bootstrap, ensembles or conformal prediction for intervals.
  • Weights are not effects. Report partial dependence instead, and remember that predictors that belong together (temperature and vacuum, r = 0.84) make partial dependence an average over combinations that never occur.

## The question: many bent lines

A straight line is the wrong shape for most things. [Splines](EXAMPLE_SPLINES_GAM.Rmd) bend it, one predictor at a time. A **neural network** goes further: it adds up many little bent lines, each of which looks at **all** predictors at once, and it finds out by itself where to bend and which predictors to combine.

That sounds like magic and is ordinary regression: there are parameters (called *weights*), there is a sum of squared errors, and a computer makes the sum small. The site's page about [handwritten digits](EXAMPLE_MNIST.rmd) uses networks to sort things into classes. Here the network predicts a **number**: the electrical power of a plant from the weather.

This page writes a network by hand, derivatives included, and finds the same solution as the package. Then it asks the question that matters more than the method: **what is a fair test?** The answer changes the ranking of the methods.

## 3. The model step by step, with formulas

### Step 1: standardise

Every variable gets mean 0 and SD 1 (with the mean and SD of the **training** data). Weights of different predictors then have comparable sizes, and the search starts in a sensible region.

```{r standardise}
standardise <- function(train, d) as.data.frame(scale(d, colMeans(train), apply(train, 2, sd)))
z <- standardise(plant, plant)
X <- as.matrix(z[, c("temperature", "vacuum", "pressure", "humidity")]); y <- z$power
```

### Step 2: one neuron

A **neuron** takes a weighted sum of the predictors and sends it through an S-shaped function, the logistic function $\sigma(u) = 1/(1 + e^{-u})$, the one from logistic regression:

$$h = \sigma(a_0 + a_1 x_1 + \dots + a_K x_K)$$

It is flat on the left, flat on the right and rises in between. The weights decide where the rise is, how steep, and in which direction.

### Step 3: the network

The **hidden layer** has $J$ neurons. The output is a linear regression on them:

$$\hat y = b_0 + \sum_{j=1}^{J} b_j\, \sigma\!\Big(a_{0j} + \sum_{k=1}^K a_{kj} x_k\Big)$$

That makes $J(K + 1) + J + 1$ weights: with 4 predictors and 10 neurons, `r 10 * 5 + 11`. Already a few S-curves add up to all kinds of shapes:

### Step 4: the loss

As in least squares, with a penalty for large weights, called **weight decay** ($\lambda$). It is the penalty of [ridge regression](EXAMPLE_REGULARIZED_REGRESSION.Rmd):

$$E(w) = \sum_i (y_i - \hat y_i)^2 + \lambda \sum w^2$$

### Step 5: the derivatives (backpropagation)

To go downhill one needs the slope of $E$ in the direction of every weight. The chain rule gives it, from the output **backwards** (Rumelhart et al., 1986). With $r_i = -2(y_i - \hat y_i)$ and the output of neuron $j$ for row $i$, $h_{ij}$:

$$\frac{\partial E}{\partial b_j} = \sum_i r_i\, h_{ij} + 2\lambda b_j, \qquad
\frac{\partial E}{\partial a_{kj}} = \sum_i \underbrace{r_i\, b_j\, h_{ij}(1 - h_{ij})}_{\text{the error of neuron } j}\, x_{ik} + 2\lambda a_{kj}$$

```{r backprop}
forward <- function(w, X, J) {
  # weights in the order that nnet uses
  K <- ncol(X)
  A <- matrix(w[1:(J * (K + 1))], K + 1)
  b <- w[-(1:(J * (K + 1)))]
  h <- plogis(cbind(1, X) %*% A)
  list(h = h, b = b, yhat = drop(cbind(1, h) %*% b))
}
loss <- function(w, X, y, J, decay) sum((y - forward(w, X, J)$yhat)^2) + decay * sum(w^2)
gradient <- function(w, X, y, J, decay) {
  f <- forward(w, X, J); r <- -2 * (y - f$yhat)
  neuron_error <- (r %o% f$b[-1]) * f$h * (1 - f$h)
  c(crossprod(cbind(1, X), neuron_error), crossprod(cbind(1, f$h), r)) + 2 * decay * w
}
set.seed(202)
w0 <- runif(2 * 5 + 3, -0.7, 0.7) # 2 neurons, 13 weights, a random start
numeric_slope <- sapply(seq_along(w0), function(i) {
  d <- replace(numeric(13), i, 1e-5)
  (loss(w0 + d, X, y, 2, 0.1) - loss(w0 - d, X, y, 2, 0.1)) / 2e-5
})
max(abs(numeric_slope / gradient(w0, X, y, 2, 0.1) - 1))                    # relative difference
```

The formula and the numerical slopes agree. (Always do this check when you write derivatives yourself.)

preds <- sapply(fits, function(m) back(drop(predict(m, z)), "power"))
round(loss_values, 1)
cbind(
  value = c(
    largest_difference_in_a_weight = max(apply(sapply(fits, function(m) m$wts), 1, function(v) {
      diff(range(v))
    })),
    typical_SD_between_the_predictions = mean(apply(preds, 1, sd)),
    RMSE_of_the_first = rmse(preds[, 1], plant$power)
  )
)
```

Six starts end at different places (loss between `r f1(min(loss_values))` and `r f1(max(loss_values))`), with quite different weights. But the predictions differ by only `r f2(mean(apply(preds, 1, sd)))` MW on average. So **single weights mean nothing**, and nobody should interpret them. The predictions are what one can use. Averaging the predictions of several networks (an *ensemble*) makes them more stable; section 6 shows by how much.

## 5. What is a fair test?

How many neurons? The usual recipe is cross-validation with random folds. But look at the data again. `r pct(mean(duplicated(plant$vacuum) | duplicated(plant$vacuum, fromLast = TRUE), 0), 1)` of the rows share their value of the vacuum, to two decimals, with other rows: `r num(length(unique(plant$vacuum)))` values in `r num(nrow(plant))` hours. The most likely explanation is that the vacuum was recorded less often than the rest, and that rows with the same value come from the **same period**. The file does not say, and its order is destroyed. But if so, then random folds put hours of the same period in the training data **and** in the test. A method that remembers its neighbours would be rewarded for remembering.

So we use two kinds of folds: **random** rows, and whole **groups** of rows with the same vacuum, so that the test has conditions that the model has never seen.

```{r folds}
set.seed(205)
group   <- as.integer(factor(plant$vacuum)); n_group <- max(group)
folds3 <- list(
  random = sample(rep(1:3, length.out = nrow(plant))),
  `new conditions` = sample(rep(1:3, length.out = n_group))[group]
)
net_predict <- function(train, test, size, decay, starts = 1, maxit = 400) {
  a <- standardise(train, train)
  b <- standardise(train, test)
  p <- sapply(starts, function(s) {
    set.seed(s)
    drop(predict(
      nnet(
        power ~ .,
        a,
        size = size,
        decay = decay,
        linout = TRUE,
        trace = FALSE,
        maxit = maxit,
        MaxNWts = 5000
      ),
      b
    ))
  })
  mean(train$power) + sd(train$power) * p
}
grid <- expand.grid(size = c(2, 5, 10, 20), decay = c(0.01, 0.1, 1))
cv <- do.call(
  cbind,
  lapply(folds3, function(f) {
    sapply(seq_len(nrow(grid)), function(i) {
      e <- numeric(nrow(plant))
      for (k in 1:3) {
        e[f == k] <- net_predict(plant[f != k, ], plant[f == k, ], grid$size[i], grid$decay[i])[,
          1
        ] -
          plant$power[f == k]
      }
      sqrt(mean(e^2))
    })
  })
)
print(round(cbind(grid, cv), 3), row.names = FALSE)
```

## 6. The network against others

Both kinds of folds again, with new folds, for seven methods: a straight line, a GAM, the 5 nearest neighbours, a random forest, the small network that the second kind of folds chose (`r best_g$size` neurons, decay `r best_g$decay`), the large one that random folds chose (`r best_r$size` neurons, decay `r best_r$decay`), and the average of three such large networks.

```{r compare}

They cannot remember single periods. The flexible ones lose a lot: the forest goes from `r f2(w("random forest", "random"))` to `r f2(w("random forest", "new"))`, the large network from `r f2(w("large network", "random"))` to `r f2(w("large network", "new"))`.
- **Averaging** three large networks changed the error from `r f2(w("large network", "new"))` to `r f2(w("3 large networks, averaged", "new"))` (new conditions) and from `r f2(w("large network", "random"))` to `r f2(w("3 large networks, averaged", "random"))` (random folds): it helped, at three times the cost.

Which of the two tests is right? It depends on the use. To fill a missing hour in the past, random folds. To forecast the power of next week, the second, and even that may be too kind, since vacuum values close to the left-out ones are still in the training data. **Choose the folds so that the test is like the use.**

The gain from all that flexibility is modest here. From the straight line to the best method with new conditions, the RMSE falls from `r f2(w("straight line", "new"))` to `r f2(min(wide$new))` MW.

## 7. What has the network learned?

The **partial dependence** of a predictor: set it to a value in every row, predict, and average. For three large networks, the small one and the GAM:

```{r partial, fig.height = 5}
set.seed(207); bg <- plant[sample(nrow(plant), 400), ]; zbg <- standardise(plant, bg)
one_net <- function(size, decay, s) {
  set.seed(s)
  nnet(power ~ ., z, size = size, decay = decay, linout = TRUE, trace = FALSE, maxit = 400)
}
nets <- c(
  lapply(1:3, function(s) one_net(best_r$size, best_r$decay, s)),

    q <- seq(quantile(plant[[v]], 0.01), quantile(plant[[v]], 0.99), length.out = 25)
    do.call(
      rbind,
      lapply(q, function(x0) {
        b2 <- bg
        b2[[v]] <- x0
        zb <- standardise(plant, b2)
        data.frame(
          predictor = v,
          x = x0,
          model = c(paste("large", 1:3), "small", "GAM"),

The GAM draws nearly the same curves. The three large networks agree with them in the middle and fan out at the ends, where rows are few and where partial dependence asks for combinations that hardly occur (a cold hour with a high vacuum). When a network and a GAM show the same picture, the GAM is the better story: it can be written down, and it comes with intervals.

## 8. Things to keep in mind

- **Standardise** the predictors and the outcome, with the means and SDs of the training data. In R's `nnet()` add `linout = TRUE` for a number.
- **Try several starts**, set the seed, and average the predictions.
- **Use decay** (or stop early). With enough of it the exact number of neurons matters little.
- **Choose with folds that look like the use**: groups, sites, times, persons.
- **Small tables**: for a few thousand rows and a handful of predictors, trees (random forest, boosting), GAMs and Gaussian processes are usually as good and less work. Networks pay off with images, sound, text and very many rows.
- **Deeper networks** have several hidden layers and other functions (ReLU instead of $\sigma$), and are trained on small batches with packages such as `torch` or `keras3`. The principles on this page are the same.
- **Outside the data** S-curves become flat, so the network predicts a constant. It never says that it does not know. ([Gaussian processes](EXAMPLE_GAUSSIAN_PROCESS.Rmd) do, with the limits shown there.)
- **No intervals and no tests** come with it. Use the bootstrap, ensembles or conformal prediction for intervals.
- **Weights are not effects.** Report partial dependence instead, and remember that predictors that belong together (temperature and vacuum, *r* = `r f2(cor(plant$temperature, plant$vacuum))`) make partial dependence an average over combinations that never occur.

## 9. Reporting the results in APA style

A report (APA 7th edition) needs the data and any dropped rows, the standardisation, the architecture and the number of weights, the loss, decay, optimiser and number of starts, how the settings were chosen, how the test was made, and the comparison with simple models. The numbers come from the R objects:

**Method** (data analysis):

> The net hourly electrical power of a combined cycle power plant (*N* = `r num(nrow(plant))` hours at full load, after removing `r sum(duplicated(raw))` exact duplicates; Tüfekci, 2014) was predicted from air temperature, air pressure, relative humidity and exhaust vacuum. Neural networks with one hidden layer (logistic units, linear output) were fitted to standardised variables by minimising the sum of squared errors with a weight-decay penalty, with the quasi-Newton optimiser of the R package nnet (Venables & Ripley, 2002). Because the vacuum takes only `r num(length(unique(plant$vacuum)))` different values and hours with the same value probably come from the same period, cross-validation was done in two ways: with random folds and with folds of whole vacuum values. The number of hidden units (2–20) and the decay (0.01–1) were chosen by 3-fold cross-validation, which gave `r best_r$size` units (`r n_weights(best_r$size)` weights) and a decay of `r best_r$decay` with random folds, and `r best_g$size` units (`r n_weights(best_g$size)` weights) and a decay of `r best_g$decay` with folds of whole vacuum values. Both networks, the average of three large ones from different random starts, linear regression, a generalized additive model, 5-nearest neighbours, and a random forest were then compared with 5-fold cross-validation on new folds. Analyses were conducted in R (Version `r paste(R.version$major, R.version$minor, sep = ".")`; R Core Team, `r R.version$year`).

**Results:**

> With random folds, the random forest had the lowest root mean squared error (RMSE = `r f2(w("random forest", "random"))` MW; Table 1). With folds of whole vacuum values, its error was `r f2(w("random forest", "new"))` MW, and the average of three large networks (`r f2(w("3 large networks, averaged", "new"))` MW), the small network (`r f2(w("small network", "new"))` MW) and the generalized additive model (`r f2(w("GAM", "new"))` MW) were more accurate, with practically the same error; linear regression had an error of `r f2(w("straight line", "new"))` MW. A single large network went from `r f2(w("large network", "random"))` to `r f2(w("large network", "new"))` MW. In the small network, the partial dependence of power on temperature spanned `r f1(spans["small", "temperature"])` MW, on the vacuum `r f1(spans["small", "vacuum"])` MW.
